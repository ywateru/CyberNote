# 需求与验收

## 目标与边界

用户要求分别交付可运行的 Mac 应用和 Android APK，UI 与对应 Apple Notes 原版逐像素对齐，交互一致，所有数据留在各自设备，不开发 iCloud。2026-11-06用户另行明确要求已配对桌面与安卓之间双向同步，按[同步架构](architecture/sync.md)实施；不扩为多人在线协作。Mac 以本机 macOS 26.4 Notes 4.13 (3146.101.28) 为基准。Android 以用户提供的 iPhone 录屏为视觉与手势基准，不套 Material 风格。两个平台共享数据语义，各自使用对应的布局。

2026-11-06手机首页新要求优先：Android改为直接进入画廊、明显＋与一键输入，文件夹退为次级入口，具体以[快速首页83](ui/android-quick-home.md)及用户保全三图为准；该范围覆盖旧iPhone逐级文件夹导航和部分编辑常驻控件，不据此扩展截图中的AI/待办/通话功能。Mac继续原版方向，其他手机附件/录音等仍沿用已证交互。

用户已授权自主开发、运行、调试和本机原版对比，无需阶段性批准。文档与实现随证据更新。不得把“近似”、“可运行”标为“逐像素通过”。

## 证据与质量门槛

1. 功能通过须在真实 Rust 存储和已安装应用上走通；浏览器 localStorage 演示不替代桌面/APK 验收。
2. 每个交互用例记录：初始内容、动作、可见结果、持久结果、失败处理。失败不能静默吞掉。
3. 同一页面原版/重建截图必须使用相同内容、布局尺寸、主题、语言、缩放。时间/光标/系统状态栏只在明示的动态区域遮罩，不得整块遮罩内容来提高分数。
4. 逐像素比较输出叠图、差异图、差异像素占比及每通道差值；任何容差都须披露，目标仍为零结构差异。未测状态为 unknown，不算 pass。
5. Android 系统键盘/状态栏与 iOS 由不同操作系统提供。应用拥有的内容区按录屏对齐，系统界面差异明确列出。低清录屏无法恢复原始字体细节，不虚报高清精确匹配。
6. 必须交付 Mac .app、Android .apk、可复现构建命令、验证记录、已知缺口。最终完整验收以前目标保持 active。
