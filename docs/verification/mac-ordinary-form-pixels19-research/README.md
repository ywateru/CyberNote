## 捕获限制与最小下一步

两输入均为有损JPEG；4:2:0会让暖色焦点环、蓝色选区和金色按钮边缘出现色晕，1px的bbox/色值差异须结合阈值敏感性解释。原版是独立表单裁片，克隆是完整窗口中的DOM模态框，背景、阴影、capture framing和合成路径不同。克隆完整图左下约 `(126,1272)` 有CUA指针，位于表单裁片之外；它和窗口背景均排除组件比较。原版裁片中没有可见独立指针，但不能由此推断其捕获时光标策略。原版AppKit与克隆WebKit的字体抗锯齿/焦点绘制不同，当前并无相同捕获方式、完整屏幕尺度与焦点时序的控制证据。

[aligned-overlay.png](aligned-overlay.png) 仅为50%混合的定位辅助。[raw-difference-amplified4.png](raw-difference-amplified4.png) 是未经颜色空间变换的RGB绝对差放大4倍并截断，包含所有捕获/颜色/选区/控件差异，不提供pass评分。原生并排、裁片、角图及叠图显式保留共有ICC；差图本身没有色彩学含义。

下一项最小调整应继续限定 **普通Mac创建表单**，不重做已对齐的800×414、标题bbox、按钮布局或说明几何：

1. 先处理面板、按钮与未选中checkbox的表面，以及角部轮廓；以本图ROI和轮廓曲线作为待对照目标，先核真实渲染的颜色管理/描边，再决定样式值，不能把截图RGB或内缩直接写成CSS。
2. 单列普通名称框的选区、灰内边与暖色焦点环；输入字左缘目标是本图142而非146。需要在准确包、同一选中状态下复拍，不把外围强金色bbox相同当焦点通过。
3. 智能标签文字的2px左移与按钮文字的1–3px差异可作随后小项；标题/说明深色覆盖差先用等同捕获排除渲染影响，再决定是否调整字体，避免凭单张JPEG统一加粗。

geometry15的受控DPR2映射仅提供后续定位线索，本研究输出仍是图像像素；任何CSS改动需开发者核当前实际映射。这里没有给出未测状态的修复方案，也没有扩展到智能表单、移动端或持久化。
