## Scope and actual code path

`src-tauri/src/lib.rs` replaces only the global media callback and registers `media_permission::lifecycle()`. No recording module, App/Editor behavior, window routing, native Android permission implementation, dependencies or lockfile changed in this permission commit. The existing cleanup candidate0b29cc0 remains a distinct prior commit. No audio plugin, worker or private framework API is added.

Global `tauri::plugin::Builder` navigation/page-load/webview-ready hooks apply to both config-created main window and JS-created separate note windows; the existing creation routes remain. The media callback reads a Rust resource from **that Webview instance's public ResourceTable**, not a label-keyed cache. Tauri Webview Eq/Hash compare only labels and are deliberately not used. Ready creates default deny if absent, but does not reset earlier page event state. Destroy captures/revokes that instance's resource; replacement same-label windows get a fresh table. Resource close also revokes. Permission reads never call `.url()`, dispatch to UI or wait on a runtime result. Own state locks use try_lock; any skipped state mutation makes the resource permanently uncertain/deny, so a missed revocation cannot preserve old Allow. No source getter is used in lifecycle callbacks either.

Only Camera/Microphone can Allow. The source allowlist checks scheme, canonical host, effective port, empty userinfo, and path `/` or `/index.html`. Android/Windows product is `http://tauri.localhost` port80; macOS/iOS/Linux custom product is `tauri://localhost` with no port. Current actual Android URL was observed in old-package snapshots. Only cfg(dev) additionally permits the configured `http://localhost:1420`; arbitrary localhost ports, HTTPS, spoofed hosts, credentials, file/data/blob/about and other local documents are denied. Mobile dev proxies with a different origin are not guessed into this list.

Default/missing/unfinished state denies. Navigation first revokes, rejects an untrusted target, and clears the previous Started URL. A late old Finished before a new Started cannot restore permission. Trusted Started records the latest local URL and revokes readiness; matching Finished may restore it. Untrusted or unknown URL in **any** navigation/Started/Finished permanently taints the instance; no later trusted Finished/Started can clear that taint. Cancelled trusted loads need no matching completion event, so normal same-entry reload can recover without an unbounded pending queue.

**Public event limitation:** there is no load id/frame/request-origin in these locked callbacks. An older Finished at the exact same canonical trusted bundle URL cannot be distinguished from the new load's Finished. This policy establishes trusted local code provenance, not that the newest reload/paint is complete. Both loads execute the same locally bundled trusted code. An external/unknown event taints permanently and cannot use that ambiguity to regain permission. Hash-only navigation may lack Started/Finished; this candidate conservatively revokes on its hook and does not claim automatic media restoration from an absent load event. Current production app has no explicit hash navigation path. Runtime behavior still needs finite verification.

## Missing requesting-frame origin and content boundary

The locked Android bridge passes only resource kind, discarding public Android request.origin. Cached main-page state alone cannot identify a requesting frame. The paired actual CSP adds `frame-src 'none'; child-src 'none'; object-src 'none'; form-action 'none'`, while keeping current asset/media/image directives. Current editor schema defines text/list/table/attachment/drawing and no iframe/object/embed node; React attachment views use img/audio/download anchors. Search of actual `src`/Rust app paths found no iframe/object/embed, dangerous HTML injection, explicit WebView navigate/loadUrl, location assignment or window.open path. The one broad `object` match was a TypeScript WeakMap type, not HTML. Separate note windows use a fixed `index.html?note=…` entry. Imported editor JSON goes through the existing schema boundary; this is not a new full schema/security audit.

The explicit CSP is configured to deny remote and same-origin frame/object loads and form navigation. Derived local documents also inherit policy; this is not a claim that frame-src alone proves every srcdoc/about:blank DOM construction impossible. The current no-frame/no-raw-HTML creation paths and editor schema remain part of this boundary. It is the chosen product boundary for the current trusted bundle; this is not per-frame native origin verification. No Permissions-Policy header or framework capability is claimed as a substitute. Should untrusted executable same-origin documents or frames become a product requirement, this kind-only callback is insufficient and must be revisited. WebView91's effective policy and controlled blocked-source/frame media attempts remain **runtime unknown** until a new package is tested. System file chooser/share flows use current native paths or download anchors, not embedded PDF objects; their finite device regression remains required.
