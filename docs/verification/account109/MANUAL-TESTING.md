## 先选测试范围

建议顺序：两个新桌面数据目录 → 登录两种入口 → 同账户双向同步 → 暂停、重启与冲突 → 少量 Android 三端 → 手机 4G / 桌面 WiFi 匿名中转。

本指南使用设置中的“账户与同步”：三端登录同一测试账户，分别确认“开启并合并”，由客户端自动发现连接。[旧手工设备同步](../../sync-usage.md)的配对串、ADB reverse 和手工 wss 地址属于另一条路线，单独记录结果。

## 启动两个独立桌面端

在一个终端中执行。保留打印出的目录，重启仍使用同一目录；下次新一轮测试再生成新目录。

```sh
ACCOUNT109_REPO=/Users/water/work/2026/Apple-Notes-Clone
ACCOUNT109_APP_BIN="$ACCOUNT109_REPO/artifacts/account109/mac-72513d12-debug-wrapper-01/CyberNote-Account109-72513d12.app/Contents/MacOS/notes-clone"
ACCOUNT109_MANUAL_ROOT=$(mktemp -d /private/tmp/account109-manual.XXXXXX)
mkdir -p "$ACCOUNT109_MANUAL_ROOT/desktop-a" "$ACCOUNT109_MANUAL_ROOT/desktop-b" "$ACCOUNT109_MANUAL_ROOT/assets"
printf '本轮数据目录：%s\n' "$ACCOUNT109_MANUAL_ROOT"
"$ACCOUNT109_APP_BIN" --data-dir "$ACCOUNT109_MANUAL_ROOT/desktop-a" &
"$ACCOUNT109_APP_BIN" --data-dir "$ACCOUNT109_MANUAL_ROOT/desktop-b" &
```

两个窗口分别视为 A/B。各目录独立保存数据库、附件、账户及设备身份，缓存和进程 lease 按数据目录隔离。同一个目录不能同时运行两个实例。不要复制 `.sync`、`.account` 或 grant 来创建第二端；不要省略 `--data-dir`。

准备一张 PNG 和一个非图片文件，放在 `assets` 内，先记录文件长度和 `shasum -a 256`。也可使用[完整用例](ACCOUNT-TEST-CASES.md#前置条件与隔离)中的固定合成资产生成命令。只用合成笔记与测试账户，便于留存证据。

使用新测试账户时可直接采用上述空桌面库。2026-11-14按[资料库独立契约](../../plan/tasks/app-account109-account-independent-library.md)调整：本地库不绑定用户名，退出后可登录其他账户，登录保持同步暂停；显式开启会将本机当前内容与新账户合并。该新行为须使用包含此修改的新包，旧候选仍可能拒绝跨账户或旧手工空间。历史桌面现场为 `/private/tmp/account109-desktop-real-90b8b28b-01/desktop-a` 和 `desktop-b`，请保留，不作为新一轮空库覆盖。

## 登录与合并

1. 两端未登录时先各写一条不同的本地笔记，正常退出再以原目录重开，确认本地保存。
2. A：设置 → 账户与同步，保留默认“应用内登录”，点击登录或创建账户，在真实托管页完成操作并返回。成功应显示预期账户，首次同步保持暂停。
3. B：选择“系统浏览器”，登录同一个测试账户，再返回 B。按 A 完成后再操作 B 的顺序登录，避免本机回调监听互相占用。
4. 分别在 A/B 开启“同步此设备”，阅读首次合并说明，点“开启并合并”。关闭设置页后观察双方本地笔记合并。
5. 在额外的新隔离桌面库中检查三条取消路径：内置窗关闭；系统浏览器打开后、尚未完成授权时回 App 取消；内置等待时点“在浏览器中继续”再取消。取消后继续编辑、正常退出重开，确认仍未登录且正文完整。
6. 补做一次“内置 → 在浏览器中继续 → 成功回到 App”，记录真实成功身份；打开页面、显示 authorizing 或取消成功都不能替代该步骤。

出现错误时记录界面安全错误及发生步骤，保留数据目录。例如 `account_auth_identity_invalid / responseMetadata / codeExchange / scope` 仍需手动复验；不要将该错误归为网络失败，也不要通过清空身份资料跳过它。凭据仅在托管页输入，不放进终端、记录或截图。

2026-11-14新增错误细分源码需新包才能验收：登录返回后失败时展开“错误详情”，记录code/stage及可选requestReason/httpStatus；上方“本次操作”与下方“账户状态”分别记录。先核对读取账户资料是否超时/被HTTP拒绝，或授权码响应是否scope校验失败。重复相同状态轮询不应抹去SignIn/Busy操作失败；一次读取状态失败后，后续读取成功应清除读取失败提示。不要把页面提示变得具体等同于登录或同步成功。

## 双桌面检查表

首次连接最多观察 120 秒，连接后的每次数据补齐最多观察 60 秒。超过预算记失败，保留当时待处理数、冲突数及安全错误。手动点“立即同步”后才恢复的结果应单列。

| 场景 | 操作 | 核对内容 |
| --- | --- | --- |
| A → B | A 新建中文标题、两段正文、粗体、清单、表格，插入 PNG 和文件 | B 正文、格式、顺序、附件归属完整；导出附件长度/SHA256 与资产一致 |
| B → A | B 新建另一条同类笔记，并修改 A 的测试笔记一处 | A 收到完整新笔记及修改，附件无重复、无错绑 |
| 暂停 / 恢复 | A 关闭“同步此设备”，A 本地新建，B 另行修改；观察至少 3 秒，再恢复 A | 暂停期间不收发，本地可保存；恢复后双方补齐 |
| 进程离线 / 重启 | 正常退出 B，A 修改，再按原目录启动 B | B 自动恢复并补齐；A/B 各再改一次均能同步 |
| 设置页关闭 | 关闭账户页后修改另一端 | 页面关闭不停止同步，重新打开状态准确 |
| 并发冲突 | 两端暂停后修改同一已同步笔记，再恢复；打开冲突页 | 两个完整版本可见；按“全部另存并解决”处理后双方保留两版及其附件 |
| 退出 / 原账户重登 | A 确认退出，双方各新建；随后 A 登录原账户并显式开启同步 | 退出期间数据相互隔离、本地可编辑；重登后按实际状态恢复补齐 |
| 更换账户 | 在单独合成测试库中完成 A→退出→B→退出→A；B登录后先不启用，再显式开启并合并 | 每次登录成功且暂停，不因原用户名或手工空间拒绝；未确认前不上传，确认后使用当前账户空间；本机正文附件保留，旧连接/邀请/版本状态不串入新空间 |

视觉对照只记“手动内容检查通过”。需要声称完整结构等价时，通过应用“导入与备份”导出备份作离线比较，核对完整 document/plainText、标题、文件夹、时间、置顶、纸张、删除/锁定状态及附件 descriptor/引用/长度/SHA256。只允许明确说明的投影 revision 和跨端物理 relativePath 差异。备份及原始数据保持私有，不直接提交 Git。没有完成结构或字节核对的项，记录为“部分通过”。

| 场景 | 操作与通过条件 |
| --- | --- |
| 桌面 → 手机 / B | A 新建带格式正文、PNG 与文件，手机及 B 均收到；导出文件长度/SHA256 一致 |

任一步失败先保留现场，核对原有数据是否仍完整。不要用 `pm clear`、卸载重装或复制授权来恢复；本轮不要求系统结束 App 后仍常驻后台。

## 手机 4G 与桌面 WiFi 的匿名中转

由测试者确认手机实际默认网络为移动数据，两个桌面走 WiFi，再进行上述双向场景。账户模式已配置匿名 Quick Tunnel 提供程序，直连失败时由正常 SDK 回退，应用层身份和加密仍生效，无需手填隧道 URL。

单独记录两件事：数据是否完整收敛，以及承载通道是否确实为中转。设备 online、连接成功、health 200、`tunnel-ready` 均不足以证明本次数据使用中转。产品普通界面不显示内部传输标签；没有读取实时 Mapping 的证据时，结果写“数据场景通过，中转路径未核实”。

若之后使用开发命令辅助验收，三端执行器仅适用于固定历史 QA、原始两桌面库、准确候选及固定私有手机快照，不适用于本指南新建的任意目录。它的 `--require-relay-02` 与 `--declare-phone-4g-desktop-wifi` 必须同时提供，并要求 A↔C、B↔C 在传输前后均有新鲜 `sync=cloudflare-tunnel` 样本。该证据是端点样本，不是逐字节路径追踪；当前不在本指南中启动该执行器。
