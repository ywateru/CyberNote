## Resolved blocking findings at the first two patches

- **P2: cached command Busy permanently prevents login retry through the error card.** `retryRequest` treats `latestError.safeError=account_busy` as a reason to issue status only. Unchanged successful polling intentionally retains that action error. An unprofiled mismatch followed by one transient lifecycle Busy therefore never dispatches a second SignIn through the error card, even after the lifecycle owner is free. Independent React-host reproduction expected two authorization calls after explicit retry but observed one. Cached action errors cannot establish current activity; an eligible explicit retry must reach the native ownership gate. Polling must remain read-only.
- **P2: a historical status Busy disables confirmed exit.** `nativeBusy` also disables the exit button. With an error terminal and persisted Busy, both login and exit are unavailable; read-only status does not itself clear that stored error. Independent reproduction expected an enabled exit button but observed disabled. Keep actual UI pending-operation guards and native lifecycle locking; provide an explicit confirmed cleanup/exit path for the historical terminal.

**Resolved by `db3c83d6`:** cached command Busy permits explicit retry of the original SignIn/SignUp with the selected surface when the current clean signedOut state or connection-retry policy permits authorization. Unchanged polling still preserves the action failure and never starts authorization. Current authorizing, cleanup and status Busy do not gain a new authorization path. Historical status Busy/provider Busy in error/signedOut now retains confirmed exit; actual UI pending work and native locking still govern concurrency.
