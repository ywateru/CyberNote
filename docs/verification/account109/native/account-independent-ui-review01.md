Unchanged successful polling intentionally retains that action error. An unprofiled mismatch followed by one transient lifecycle Busy therefore never dispatches a second SignIn through the error card, even after the lifecycle owner is free. Independent React-host reproduction expected two authorization calls after explicit retry but observed one. Cached action errors cannot establish current activity; an eligible explicit retry must reach the native ownership gate. Polling must remain read-only.

With an error terminal and persisted Busy, both login and exit are unavailable; read-only status does not itself clear that stored error. Independent reproduction expected an enabled exit button but observed disabled. Keep actual UI pending-operation guards and native lifecycle locking; provide an explicit confirmed cleanup/exit path for the historical terminal.
