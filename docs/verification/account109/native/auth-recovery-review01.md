## Source findings

- **Explicit retained-owner retry:** only an existing binding plus error/network status selects the new native recovery path in `SyncNow`. It serializes through the lifecycle owner, advances generation, seals the previous network, calls retained `auth.restore`, and reuses strict `bind`. It does not logout, open a browser, replace ownership, add an IPC command, or set enabled true. `Status` remains read-only. An originally paused binding ends paused; only a binding whose persisted enabled flag is true proceeds to network start. Existing issuer/subject/profile/workspace/device checks are retained.
- **Cancellation/generation:** production `recovery::run` checks ownership before restore, after refresh, and after bind; `Runtime::bind` additionally checks the passed generation after the awaited coordinator profile and before workspace/binding writes. The command publishes recovery errors only for its current generation. SignOut/Cancel/exit retain their generation invalidation and lifecycle draining. Focused effect tests cover invalidation during refresh and profile waits, for both enabled settings, with no late bound/network effect. This establishes those boundaries; it is not an exhaustive scheduler interleaving proof of the entire existing account lifecycle.
- **Replacement authorization fence:** native `authorization_mode` now admits replacement cleanup only for the finite rejected-refresh classifications supplied by the reviewed auth contract. Network, unknown, configuration, storage, ownership, cleanup, protocol and invalid-response categories do not acquire replacement-logout permission. Initial authorization retries without a profile may begin without replacement logout; the sole auth owner still rejects a retained grant as Busy. UI and native finite network/rejection rules agree. The classification meaning must come from this new source/candidate, never from the older 39c1420 binary.
- **Actual UI action:** the visible retry button calls `request(connectionRetry)`; network-error profiles choose the real `syncNow` command even with enabled false. Polling still issues only status. Unsupported errors get no misleading status-only retry button. Paused recovery gets a paused-success notice; errors do not get a success notice. Existing enable confirmation and trusted account IPC gates are unchanged. The component continues to show authorizing controls for a pending partial profile, and its existing duplicate-action/cancellation guards remain.
- **No-session aftermath:** a successful replacement logout can be followed by discovery/browser failure while the old bound profile remains. Recovery `restore(None)` maps to `identitySession`; native does not silently authorize this profile or infer an invalid grant. The UI explicitly instructs confirmed SignOut, then login with the original account. The actual SignOut control remains available for the profile. Its existing native path seals/drains the network, performs explicit owner cleanup, sets enabled false and clears status, preserving the ownership binding; when no grant exists, AuthClient logout returns successfully without an upstream request. Subsequent SignIn uses strict original bind. Cleanup failure remains a failure and does not report signedOut. This sequence was traced in source; it was not exercised through a real App in this review.
- **Privacy/scope:** only finite error categories select actions. No raw upstream error, URL, token, grant, workspace override or credential input is added. Unknown errors remain blocked from replacement authorization. Original notes, attachments, encryption/session ownership and source-export manifest policy are outside this increment.
