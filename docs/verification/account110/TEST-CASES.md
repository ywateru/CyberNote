# 账户设备操作测试用例

本用例的预期来自[设备契约](../../architecture/account-device-actions.md)和[界面契约](../../ui/account-sync.md)。此文件是测试计划；实际通过范围必须以独立执行回执为准，不能以本表预期当结果。

2026-11-15的[当前结果](RESULT-LATEST.md)与[双客户端手动入口](MANUAL-TESTING.md)已整理。D01–D10、D12的相关桌面场景由首轮已完成前置、独立续验及GUI共同覆盖；D11的初始暂停目录已实测，启用后再暂停并请求拒绝主要由模块检查覆盖，未单列完整双端实机流程。C组按各模块报告及GUI范围阅读，不能将整张计划表或Android标成全部实测通过。原fresh-live03超时保留，续验结果另列。

## 环境和数据

同一台 Mac 运行两个真实原生进程 A、B，各自全新的绝对 `--data-dir`，通过同一托管认证系统分别登录同一测试账户。名称分别为“本机测试 A”“本机测试 B”，登记ID、协议身份和 Noise key各不相同。默认原库不参与；不得复制 grant、binding、Noise 私钥或数据库来制造第二端。

各端创建一篇不同的中文格式笔记，正文包含多段、粗体及清单；每端至少一个不同附件，保存预期完整文档和附件 SHA256。目录统计以真实已保存数据为准。只读核对可以使用生产命令驱动器，传输必须经过真实原生账户/网络实现，不允许直接注入 inbox 或写对端数据库。

## 双客户端主要用例

| ID | 步骤 | 预期及必须保留的证据 |
| --- | --- | --- |
| D01 | A、B 分别正常登录，均保持暂停 | 各自账户设备列表有两台稳定ID设备；两端独立注册，同名不合并；在线但“同步已暂停”，无内容传输 |
| D02 | 改名A，再退出并正常启动A | B看到新名称；A登记ID保持；不新增一个虚假离线A；原笔记保留 |
| D03 | 只在A编辑笔记，保存后等待目录刷新 | A数量与最后更新时间正确；B显示A最新摘要；不改B正文；心跳持续时笔记更新时间不变 |
| D04 | 显式允许A和B同步，等待超过旧自动cycle周期 | 两端独有文档和附件不交换；开启本身不广播；目录显示可同步 |
| D05 | A选择B，打开方向对话框，改方向后取消 | 无syncDevice命令，无数据变化；取消/Escape恢复发起控件焦点 |
| D06 | A对B执行push | A独有内容在B持久接收并最终应用；格式/附件原字节匹配；B独有内容不出现在A，A无B独有附件；结果说明本次传输完成 |
| D07 | 新建A2、B2；A对B执行pull | B2到A，A2不到B；比较完整文档与附件SHA；B保留原独有笔记 |
| D08 | 新建A3、B3；A对B执行both | A3、B3在两端收敛；正文、格式、附件相同，未覆盖先前独有内容 |
| D09 | 成功后继续在A编辑，等待空闲观察窗口 | B不收到新版本；只有再次显式操作才交换；重连不隐式重放上次方向 |
| D10 | 正常退出B，超过presence lease后刷新A | B行仍保留、显示离线，隐藏历史摘要；对B不能启动/排队；重新启动B后同ID在线且仍不自动传内容 |
| D11 | B暂停同步但保持登录 | A仍看到B在线且同步已暂停；向B请求明确拒绝；B本地编辑继续有效 |
| D12 | 两端正常退出、重启，核对保存 | 已接收及本地独有文档/附件保留；名称/registry ID稳定；不凭重启补发任务 |

每个方向至少核对：发送前两端全集、发送后两端全集、完整文档规范化比较、附件清单与原字节SHA；仅比较标题/数量/最近同步时间不足以通过。

## 模块和负向边界

| ID | 目标 | 预期 |
| --- | --- | --- |
| C01 | 设备API跨账户、跨产品、伪造transport session | 服务端拒绝/隔离，响应没有其他owner设备或sessionKey |
| C02 | registry超额、非法名字/UUID/摘要/多余字段/超大body | 明确有限错误，不自动淘汰离线设备，不把缺失摘要变0 |
| C03 | presence旧generation迟到、旧session注销、协调epoch变化 | 新presence不被旧请求覆盖；长期记录不因短期GC删除 |
| C04 | 空库、锁定笔记、回收站、文件夹、历史版本 | 0与未知区分；锁定计数但不解锁，回收站/文件夹/历史版本不计，lastUpdated只源于有效笔记 |
| C05 | 三个真实网络服务A/B/C，仅A选B | C内容不变；A/B没有后台反向worker，未明确握手的旧账户peer不能发内容RPC |
| C06 | 目标离线/不兼容/暂停，账户切换或关闭许可时的在途操作 | 有限失败/取消，任务固定目标和方向，迟到回执不覆盖新账户；不无限重试或自动改投 |
| C07 | UI目标消失、同名设备、重复确认、状态轮询与失败重试 | 一次确认最多一次正确目标/方向IPC；取消/轮询/改名/刷新不发内容命令 |
| C08 | 键盘、窄屏、深色主题与较大字号 | 模态隔离、初始取消焦点、方向选择可键盘操作、Tab闭环、名称换行且触达区足够 |
| C09 | 原高级手工同步 | 无账户policy的原双向同步行为保留，受影响回归通过 |
| C10 | 服务未部署新API、旧客户端无摘要/方向能力 | 明确不可用，不回退全网自动同步或把临时目录冒充完整账户设备 |
