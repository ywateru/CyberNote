# Real Store account staging publication reproduction

The existing account staging path conflicts with the production blob publisher's accepted source directory. A controlled real-Store loopback reproduction isolates that mismatch: the exact account layout fails at `source-path / sync_invalid`, whereas changing only the test staging directory to the publisher's existing canonical directory makes both tests pass. No product fix was made.

Production references at candidate `9e8a4011`: `SyncAdapter::activate_account` in `src-tauri/src/sync/adapter.rs` constructs `SyncService` with `<root>/.account/staging/<device>`. `StoreBackend::store_blob` calls `BlobStorage::publish_staged`, whose check in `src-tauri/src/store/synchronization/blob.rs` accepts only `<root>/.sync/network-staging/<hash>-<size>.part`. It rejects the account parent before opening or hashing the file. The fixed `sync_invalid` becomes backend `Protocol`, wire `Invalid`, and finally caller `Protocol`.

The fixture uses production StoreBackend, Session, backend epoch and real Gate with directly admitted synthetic Claims. Both identities are independently generated. After pure pair, both services/Gates/identities/Stores/Sessions are shut down and dropped, then reopened from their own temporary persistent data, assigned new loopback routes, and used for one push without pairing again. It creates a valid 1x1 PNG and a distinct 49,169-byte ordinary binary attachment through Store attachment APIs and document references. No original/owned App library, grant, Noise credential, OAuth/SDK, GUI, external network or default store is used.

## Interpretation and proposed fix boundary

This is strong reproduction plus source evidence for a deterministic account attachment publication defect. It does not record the exact publisher branch in the prior live App run, and must not replace that original receipt or backfill its diagnostics. It does not establish App direction acceptance, full wire equality or Session application. Real Gate is exercised with synthetic admitted Claims and no SDK/lifecycle binding; route ports are reassigned without asserting inequality; the pure-pair content-call helper omits read_blob_chunk. These coverage limits were raised by Erdos and remain explicit.

A production fix must preserve account/manual namespace isolation and all existing filename, directory/symlink, inode/stability, hash/size, locking, quota, rename and fsync checks. Prefer a fixed Manual/Account(device) staging capability captured from the trusted local identity and shared by service and publisher. Do not accept an arbitrary caller-provided expected path or remove the publisher guard. Switching production accounts to the legacy canonical directory needs separate proof about old manual partials, device/epoch isolation and adoption; the passing test control alone does not authorize that design.

Test-only source is on `codex/account110-real-store-repro-run`: `64ce1bb2` finite RPC traces, fixture picks `fa19e688` and `03bbd5e8` (author originals `0d23a748` / `506ee61d`), then `07b94f11` exact layout/control and fixed publisher-branch marker. The default baseline attachment test deliberately fails before the product fix; this is investigation source for review, not a passing product patch. The diagnostic snippets are cfg(test) and preserve rejection behavior. No manifest pins were changed.
