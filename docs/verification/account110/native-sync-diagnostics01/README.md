# Account110 finite native sync failure diagnostics

Exact product commit: `c31a9b1c1cc4a7d56c73544fef987024b4111c3f`, based on `0a4a4cda80d926c470cfbc8d5cef3bb2937ca58a`. Contract read: `47572b955d75ac7e7bffd1f46d2588eb454de1b0`. Independent review pending.

The separate live02 diagnosis ended with a failed selected-device operation and only `account_sync_failed`. The existing generic conversion discarded the typed SyncError, so that evidence does not identify pairing versus transfer failure. This patch adds finite classification for a future authorized observation; it neither changes transport nor establishes the live failure's cause.

Only `account/types.rs` and `account/transport.rs` change. `Error::SyncAt` preserves a fixed stage and the existing payload-free SyncError enum. SafeError serializes `syncStage` and `syncReason` together only for this variant, with the unchanged `account_sync_failed` code and existing fixed message. Stages are `pair`, `recoverPairing`, `transfer`, `retirement`. Reasons are the exact 15 existing snake_case SyncError values recorded in receipt.json. There is no provider message, endpoint, identity, arbitrary diagnostic string or new input field.

The six conversion points are only the actual pair/recover/transfer calls and their disconnect retirement closures inside `transfer_target`. The generic `From<SyncError>` conversion elsewhere is unchanged. Unclassified native join failures and deadlines do not invent a typed reason. A retirement diagnostic describes the failing disconnect call; it does not independently identify which preceding action retired. Cancellation and any higher-priority retained retirement failure still override the action result exactly as before. The blocking helper, network implementation, deadlines, gate rules, admission fence, ownership permits and join/drain code are unchanged.

One exact-source, default-parallel complete account run passed **78/78, zero failed, zero ignored**. Three new tests cover all 60 stage/reason serialized combinations and omission outside SyncAt, preservation of action stages without expanding authorization fences, and classified retirement-error precedence with cancellation still winning. The group also retains existing generic panic classification, late admission, request cancellation/blocked backend retirement, real owner future sizing and 512KiB stack regression coverage. Existing compiler warnings and the expected synthetic blocking-action panic are preserved in the raw log.

Testing used the sole shared target, offline/locked jobs2, development/test debug0 and incremental0. Minimum observed free space was 10,578,083,840 bytes, above the monitored 6GiB floor. Cargo exited normally and the target lease was released before archiving. No further rerun was started. No App, live/owned data-dir, login, grant, Noise file, device, external account request, package or manifest was accessed/run/changed for this implementation. Synthetic tests use temporary data and loopback endpoints.

Exact command, environment and product file hashes are in receipt.json; SHA256SUMS covers the receipt, summary and raw test output. Frontend strict parsing, runner diagnostic preservation, independent approval and any subsequent real-client observation are separate work.
