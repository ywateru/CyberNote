# 账户设备同步交付与验证结果

2026-11-15。本轮已完成账户设备列表、指定设备推送／拉取／双向同步，以及本机两个独立客户端的实际验证。结果由首次运行的已完成前置检查、独立续验和实机界面核对共同提供；原失败记录保留，不能称首次自动运行整体通过。

## 功能与入口

- 列出同一账户已登记的设备，离线记录保留；支持修改本机名称，同名设备不会合并。
- 在线设备显示未删除笔记数和笔记最后更新时间；空库、未知、离线分别显示，不以心跳代替笔记时间。
- 点击远端设备，在统一模态框选择推送、拉取或双向。方向以本机为准，保留各端独有内容。
- “同步此设备”是收发许可；开启、发现、刷新、重连和操作完成后的编辑均不自动广播内容。
- 本地资料库独立于登录账户，未登录也可编辑；已有冲突保全与附件安全应用规则继续有效。

## 本机双客户端结果

两端从不同空目录建立，分别通过真实托管表单登录同一测试账户；没有复制授权、Noise 私钥或数据库制造第二端。默认原资料库未参与收发。

| 场景 | 实际结果及范围 |
| --- | --- |
| 独立资料库、保存与重启 | 首轮创建不同中文格式笔记、PNG 和 256 KiB 以上二进制附件；正常关闭重开后完整保留 |
| 目录、改名、摘要 | 双方在线发现、稳定登记 ID、名称、笔记数量与真实更新时间通过；暂停仍可发现 |
| 开启与刷新 | 开启许可、发现和显式刷新均未传输未请求内容 |
| 推送 A→B | [独立单次请求成功](native/push-continuation01/README.md)；续验从原样本摘要及确定性附件重建预期，核对完整接收集合与禁止反向传输 |
| 拉取 B→A | 单次请求观察到进行中及成功终态；B 的内容到 A，A 的新独有内容和协议／附件数据未到 B |
| 双向 | 单次请求成功，双方完整文档、格式、附件元数据、磁盘 SHA256 和生产读取字节一致 |
| 空闲编辑与新增 | 两端在共享笔记上分别增加格式文本并新增笔记；对端内容及协议版本指纹保持不变 |
| 离线与恢复 | B 正常关闭、租约过期后仍留在 A 的列表，显示离线并隐藏摘要；重开后同 ID、同名，不补发内容 |
| 最终双端重启 | 两端正常关闭重开后，全部正文、格式、附件原字节及预期本地分歧保留 |
| GUI | 在线／离线列表、真实摘要、改名模态取消、三方向单选、键盘方向切换、Tab 闭环、Escape／取消后的焦点恢复通过 |

独立续验有 **11 项检查、110 条完整文档及双附件核验记录**；110 是跨阶段重复核对次数，不是 110 篇不同笔记。5 个原生实例自然退出 0，77 个排除检查进程和 42 个协议指纹检查进程全部关闭。详见[精确续验结果](native/owned-continuation01/README.md)和[实际结果独审](../../plan/reviews/app-account110-owned-continuation-live-01.md)。

GUI 后另行正常重开核对，全部笔记 semantic SHA 集合与最终续验一致，A 为 10 篇／20 个附件，B 为 9 篇／18 个附件；均无账户错误或运行中的设备操作，并正常退出。GUI holder 与后续重开核对是不同进程，不能写成同一次连续采样。详见[GUI、进程与收尾记录](native/post-gui01/README.md)。

最终 A10／B9 是刻意进行空闲新增和离线编辑后的预期结果，说明没有自动交换；双向同步完成时已另行核对收敛。两个测试库保留供手动使用，目前测试实例已关闭。

## 修复与保留的失败

实际排查修复了组合 future 的原生栈占用、重复的 60 秒准备期限，以及账户附件暂存与发布路径不一致。最后一项使用生产 Store 适配器的失败／成功对照定位：账户服务写入 `.account/staging/<device>`，旧发布器却只接受手工目录。修复以内部 `NetworkStaging` 能力共享路径定义，保留账户隔离及目录、文件身份、大小、SHA256、原子发布检查。[复现](native/store-staging-reproducer01/README.md)、[修复回归](native/staging-capability01/README.md)及[独审](../../plan/reviews/app-account110-staging-capability-01.md)均保留。

- 新包首次 owned 恢复曾报目录不可用，尚未提交推送；同包后续恢复及推送成功。[首结果](native/staging-fix-owned-push01/README.md)保留，不据此认定永久目录故障。
- fresh-live03 在推送场景报 `NATIVE_TIMEOUT`。后续使用原 `syncOnce` 的一次同库推送未复现，三个桥接表达式均返回；原超时的精确调用与原因仍未知。[原失败](native/staging-fix-live03/README.md)没有改为通过。
- 本轮没有重新验收 Android／4G、中转强制路线、全部主题字号、系统睡眠或长期后台运行。桌面传输主要通过原生命令驱动，GUI 仅覆盖上表明确列出的交互，不等于三种传输都由鼠标点击完成。
- D11 的初始暂停发现已实测；启用后再次暂停并请求拒绝，主要由模块检查覆盖，未完成单列的完整双端实机流程。手动步骤见指南，不能据模块结果扩大桌面实测范围。

模块检查分组之间存在重叠，不相加宣称唯一总用例数。完整原始失败、构建与审阅链见[任务记录](../../plan/tasks/app-account110-device-actions.md)。
