Date: 2026-11-03. The preceding real 6c155 package preserved the full long-query value, but its viewport stayed at the beginning after Command-Right and tail continuation. That runtime failure remains recorded in `../runtime-search-editor-01/selfcheck.md`; this preparation is not a runtime fix claim.

The bounded AppKit check creates no window and performs no user-interface actions. It instantiates the current actual `NotesUISearchField` production class and standard `NSSearchField`, applying the same formatter, placeholder, search settings and borderless style as production. It reads public properties only; these are fresh no-window objects, not objects read from the running 6c155 process. Both report `scrollable=false`, `usesSingleLineMode=true`, `wraps=false`. The production class's text bounds remain the measured `{{20.25, 6}, {133.75, 16}}` at 178×28. Source and actual output are `no-window-properties.m` and `no-window-properties.json`.

The check compiled and ran with exit 0, with no compiler output. It imported the production native source with SHA-256 `4115f4d503e08e6d126367f40a02aff8be1f5a7df1a7009bed5b86af8083d99e`; the exact preceding source is preserved at `../runtime-search-editor-01/toolbar-source.m`. No actual field editor or private clip-view properties were inspected in this no-window check.

Apple's [NSCell.isScrollable documentation](https://developer.apple.com/documentation/appkit/nscell/isscrollable?changes=_3%2C_3) defines the property as allowing excess text to scroll beyond the cell bounds. The installed public SDK header `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/AppKit.framework/Headers/NSCell.h:126` declares `scrollable` with getter `isScrollable` and notes that enabling it sets wraps to NO; line 207 separately declares `usesSingleLineMode`. Single-line mode is already true in the measured objects. This supports a minimal public-property candidate rather than editing the private clip view; the cause-and-fix inference still requires the next actual package check.

The prepared production change is one line after native search style initialization: `[(NSSearchFieldCell *)self.search.cell setScrollable:YES];`. The complete resulting `toolbar.m` SHA-256 is `2d23fed63051e1841ee8f954d02474b659216893f79a65ed64cef651c32d02c0`. It retains the same native cell/editor, public edit/select geometry, formatter, selection handling, clear button and accent configuration.
