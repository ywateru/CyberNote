# FIX03：晚到动作的受控顺序（未执行）

此文是未来回归的动作协议，当前没有实现延迟控制或执行真实窗口，不含通过结论。先按 `README.md` 导入合成夹具，仅操作克隆，不实际发送分享。

## 共同记录与暂停点

W1为主窗，W2为通过显式入口创建的独立窗；必须记录运行时实际窗口ID，不能用两个组件或虚构标签代替真实窗口。N为目标笔记ID。每个步骤记录单调动作序号、实际操作时间、窗口ID、进程会话ID、后端授权epoch及N的access epoch、文档revision、本地请求generation、待保存数、编辑器是否挂载、当前选择、可见正文/预览/搜索结果，以及动作结果。

后续测试控制层应区分两个暂停位置并记录是否真的到达：

- **执行前暂停**：命令尚未进入真实后端Store互斥区；释放后仍必须经过实时授权检查，可测试旧epoch请求执行时被拒绝。
- **响应交付前暂停**：真实命令已经执行，结果已带会话/epoch/revision标签；暂停交付前端，释放后可测试旧响应不会回灌。绝不能把这类结果当作“后端在锁后读取成功”。

不以固定sleep制造“可能在途”，必须用请求ID和可观察的到达/释放ACK。延迟适配器不能改写真实返回值、绕开Store检查或直接设置React/编辑器状态。普通GUI操作用于真实窗口复现；控制层若需要测试构建，应单列其差异，生产安装版同步路径另行核对。

## S1：prepare前已排队的合法保存，确认成功后撤销授权

1. W1/W2正确解锁N，记录同一会话/授权。W2编辑加入 `FIX03-SAVED-BEFORE-PREPARE`，确保真实save已排队但尚未确认；在执行前暂停。
2. W1请求关闭全部锁定笔记。记录prepare operation/version及参与窗口集合。W2冻结N的新编辑/外发，开始排空prepare之前允许的保存。
3. 释放W2保存。真实后端在允许的旧epoch排空窗口中接受它；W2只在返回明确成功且pendingDocs清空后ACK。不能把吞掉异常的Promise resolve当作保存成功。
4. 全部ACK后撤销密钥、提升授权版本并commit通知。W2卸载正文编辑器/历史，清除缓存、预览、搜索、格式/绘画目标和媒体URL。
5. 再正确解锁N核对标记确已持久；锁会话关闭期间任何新正文读/写/文本外发均拒绝。不得以空文档保存完成“清除”。

## S2：prepare前保存失败或revision冲突，关闭必须失败

1. 重复S1到prepare；使用真实revision冲突或受控存储错误使待保存返回明确失败，保留pendingDocs。
2. 观察W2不能发送成功ACK，W1关闭返回可见错误；授权仍有效、可恢复编辑/重试，未确认内容仍在窗口中。
3. 不允许静默丢pendingDoc、hydrate旧正文覆盖本地编辑、只等flush resolve就commit，或用重启规避未保存状态。
4. 重试保存成功后再真实关闭，核对持久标记及版本顺序。

## S3：ACK后/commit后晚到的旧保存

1. 在N已正常锁定并解锁的状态捕获一个真实合法保存的旧epoch参数，但在执行前暂停；明确该请求不属于已ACK排空集合。
2. 完成prepare/ACK/commit撤销。释放旧保存，后端实时拒绝过期授权。检查数据库revision/密文未被该请求修改，窗口不重新显示其返回值。
3. 对普通未锁定N再重复“W2旧明文保存 → W1加锁 → 释放旧保存”。后端必须把normal→locked边界纳入epoch检查，不能因发起时未锁而覆盖锁后密文。

## R1：已执行正文/工作区响应晚交付

1. W2发起真实workspace/正文读，在执行成功后、交付前暂停，记录结果标签和正文合成标记，不实际复制或分享。
2. W1完成撤销；W2清理编辑器与派生缓存。释放旧结果，前端须因session/epoch/generation过期丢弃。
3. 核对正文、预览、搜索、find、格式/绘画目标均未恢复；旧编辑器实例/history已销毁。重新聚焦、切笔记再回来也不恢复。
4. 再发新读，必须由实时Rust状态返回锁定态/拒绝；不能只检查按钮置灰。

## R2：异步媒体/文本外发来源

含附件笔记目前不能锁定，不能为覆盖测试而绕过该限制。附件读的晚到清理应在允许的删除/导入失效等目标上测试，记录成功与失败回调都受generation约束、对象URL释放，删除后不复活媒体。

锁定笔记的拷贝/分享文本应从带版本标签的实时Rust读取。把此读取响应暂停于交付前，完成撤销后释放，外发适配器不得接收到过期文本。无需实际向第三方发送内容。用户先前明确复制到操作系统剪贴板或交给系统分享的副本不在可撤销范围；不检查、不清空用户剪贴板，也不无限等待系统分享完成。

## E1：窗口集合变化、事件丢失与启动恢复

1. prepare期间新开W3或新读N：不能取得目标明文，也不能绕过参与者快照。记录真实窗口ID/加入顺序。
2. 参与窗口在ACK前消失或超时：关闭失败并恢复窗口可用授权，待保存不能静默丢弃。恢复后重新发起明确操作。
3. 丢prepare：该窗口不ACK，所以关闭不能成功。丢commit：已prepare的窗口保持挂起，直到可信snapshot同步完成，不自行恢复旧明文。
4. W2从后台/焦点恢复以及新窗口启动时，先同步后端会话/epoch再显示缓存正文。冷启动必须生成新会话并无旧密钥；旧进程的任何响应标签都不能接受。

## D1：合成密文的解锁验证

导入四份冻结归档（外层可导入），记录导入前后已有本地数据与密文hash。合法富文档/绘画正确密码正常，错误密码不发布密钥。两份非法文档正确密码必须在发布密钥或明文前明确拒绝，原密文不改、其他已授权笔记状态不变。之后workspace/搜索/正文读不能看到非法内部合成标记。再正常解锁合法文档并保存/关闭/冷启动，确认没有把有效旧绘画或富文档一并拒绝。
