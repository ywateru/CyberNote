# Android 输入法再次反馈：本次现场

2026-11-10。原 Samsung SM-G9500 重新接入后，对用户“编辑时又无法弹出输入法”的反馈保留现场并做一次正文点按。此前连接缺席记录保留在同一证据目录，不当作产品故障。

初始仍为 CyberNote 编辑页，系统没有活动的 served InputConnection，也没有键盘显示请求；IME 窗口不可见。仅凭这些系统字段不能证明 DOM activeElement 或会话内部状态，更不能确定哪个先前动作使文本输入连接结束。

在确认同一页面、正文空白位置后，只点按正文一次。随即建立活动的 InputConnection，显示请求变为 true，完整微信九宫格键盘出现。CyberNote PID3298 和微信输入法服务 PID13994 保持不变；没有重启、切换输入法、安装、改设置或输入正文。

本次没有复现上次“已有显示请求、输入法却没有可见按键”的空窗异常，也没有证明永久修复或排除历史间歇问题。当前结果只能说明该现场可通过正常正文点按进入输入状态；最初进入非输入状态的历史触发未知。现场安装仍是此前 v2 诊断包，本次不是尚未构建的106普通包验收。

完整动作、字段、SHA及安全按键裁图在 `artifacts/keyboard-recurrence-20261110/live-02/`。原截图含用户笔记，仅限本地证据；可分享图为 `bodytap-after-keys-only.png`。作者报告为该目录 `report.md`。[不同代理独立复核](../../plan/reviews/app-keyboard-recurrence-live02-independent.md)已接受14份冻结文件、唯一点按链和原图精确裁图，以及上述结论边界。设备操作已停止，没有为未复现现象添加强制弹出或重启逻辑。
