# CyberBus 核心功能 UI 手动验收

本轮按 2026-11-18 的收敛要求交付：命令行检查由开发执行，本页 UI 操作由用户执行。下列复选框初始均为未执行，不能由模块测试或网络工具的结果代填。具体组合构建、命令和已知限制见 [验证状态](README.md)。

## 准备两个独立安装

优先使用两台 Mac 的同版本原生应用；也可在一台 Mac 启动两个独立资料库。不要把浏览器中的 Vite 页面作为账户/同步验收应用。不要复制一个已登录资料库来制造第二台设备，两个安装须分别生成身份、分别登录。

同机测试使用构建后的真实可执行文件，并显式传入绝对路径。示例中的 `binary` 须指向本轮验证状态记录的构建产物，A、B 资料库应是新目录：

```sh
binary='/Users/water/work/2026/Apple-Notes-Clone/src-tauri/target/debug/notes-clone'
"$binary" --data-dir "$HOME/Library/Application Support/CyberNote-CyberBus-QA-A"
```

在另一终端启动 B：

```sh
binary='/Users/water/work/2026/Apple-Notes-Clone/src-tauri/target/debug/notes-clone'
"$binary" --data-dir "$HOME/Library/Application Support/CyberNote-CyberBus-QA-B"
```

以上产物路径须以最终构建记录为准；若构建未通过，不运行旧二进制冒充本轮。保留两个资料库供问题复现，关闭应用后再备份。首次系统 Keychain 授权提示应按正常应用提示处理；拒绝授权时应用应明确报错，不能悄悄更换设备身份。

桌面 OAuth 回调固定为 `127.0.0.1:17897`，同机两个安装**依次登录**，一个授权事务结束后再在另一端开始。系统浏览器已登录其他账户时，先核对登录页账户；不得把授权 URL、callback、token 或密码贴入问题报告。

准备同一个测试账户供 A、B 使用，另备不同账户 C（可选负例）。准备一张可辨认 PNG 和一个非空文件，保留原件用于比对。打开设置中的「账户与同步」，将 A 命名为 `QA-A`、B 命名为 `QA-B`。

## 核心必测清单

| 勾选 | 编号 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| [ ] | UI-01 本地基础 | 未登录时在 A 新建中文笔记，输入标题、段落、列表、待办、粗体，加入 PNG 和文件；关闭重开 | 全文、格式、图片和文件仍可读；本地使用不要求登录 |
| [ ] | UI-02 登录取消 | A 点击「登录」，在授权期间取消；再重新登录 | 取消后仍可编辑本地笔记；迟到的旧授权不完成下一次事务；新登录可正常结束 |
| [ ] | UI-03 双端登录与暂停发现 | A、B 依次登录同一账户，不开启内容同步，等设备列表更新，可点「刷新设备」 | 两端显示本机和另一安装，登录后同步默认暂停；笔记正文和附件没有自动传到另一端；普通空库摘要为真实零值或明确未知，不凭空显示内容 |
| [ ] | UI-04 改名及离线 | 修改 A 名称，观察 B；退出 A 应用，观察 B，再重启 A | 名称更新；A 离线后有明确离线状态，不能用旧摘要伪装在线；重开后同一设备恢复，不产生重复安装条目 |
| [ ] | UI-05 开启确认 | A、B 分别开启同步，阅读合并提示，先取消一次，再确认 | 取消不改变同步意图；确认只允许后续显式内容操作，开启本身不自动广播笔记；已存在的本地笔记和附件保留 |
| [ ] | UI-06 推送 | B 新建 `仅B保留`。A 选择 B →「推送到此设备」→确认 | A 的完整中文笔记到达 B，格式、待办、PNG 和文件可打开；B 原有内容保留；`仅B保留`不会因此回传 A；成功提示之后重开 B 内容仍在 |
| [ ] | UI-07 拉取 | B 修改刚收到的中文笔记并新增文件；A 新建 `仅A保留`。A 选择 B →「从此设备拉取」→确认 | A 获得 B 的修改及附件；`仅A保留`不会因此上传到 B；两端独有内容不被整库覆盖 |
| [ ] | UI-08 双向 | A、B 各新建一条独有笔记，A 选择 B →「双向同步」→确认 | 两端均获得对方内容，实体不重复；已传附件能正常打开；操作进度最终有明确成功或失败，不能永久停在完成前 |
| [ ] | UI-09 重启恢复 | 两端完全关闭，分别重开；观察登录、设备名、暂停意图，再执行一次明确双向同步 | 登录可从受保护存储恢复，安装身份和名称保持；未完成任务不会自动重放为成功；内容和附件仍一致 |
| [ ] | UI-10 暂停 | A 暂停内容同步，B 保持运行并编辑，尝试从 B 向 A 同步；随后 A 重新开启并主动同步 | 暂停期间仍可看设备，不能接收/发起被禁止的内容；失败显示可理解原因；重新开启仍需明确操作，最终可收敛 |
| [ ] | UI-11 退出与再登录 | A 退出账户，检查本库，再重新登录同一账户 | 本机笔记和附件保留；旧连接和在途任务停止；重新登录默认暂停；不能把本地退出成功理解为旧 CyberGrid 授权已云端撤销 |
| [ ] | UI-12 错误反馈 | 登录后断网，刷新设备或发起同步；恢复网络后重试 | 显示连接/认证/同步错误，不能假成功或把授权失效仅显示成正常暂停；恢复后可通过明确重试继续 |

正文比对不只看标题/数量：逐项检查中文段落、粗体、列表层级、待办状态、图片尺寸/内容、文件名和打开后的文件内容。必要时把收到的文件另存后与原件计算 SHA256；不能仅凭缩略图认定附件字节一致。

## 第二轮手动回归

核心清单完成后，再执行下列情形；Android 和异网络需记录实际设备/系统/网络，未执行不得标通过。

| 勾选 | 编号 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| [ ] | UI-13 编辑中接收 | A 正在中文输入法组合输入、编辑同一笔记；B 修改后推送 | 活跃编辑不被突然替换，焦点/输入法/Undo 保持；退出编辑安全点后待应用内容或冲突有明确入口 |
| [ ] | UI-14 并发冲突 | 先同步同一笔记；断开两端网络，分别修改同一实体并加不同附件；恢复网络后双向 | 两个分支可查看/恢复，附件完整；不能按时钟静默丢掉其中一个版本 |
| [ ] | UI-15 删除与恢复 | 同步一条笔记，A 删除、B 离线编辑后重连；再测回收站恢复 | 按既有因果/冲突规则处理，不能旧端无提示复活已删除内容；恢复后内容可读 |
| [ ] | UI-16 旧库迁移 | 仅在已备份的旧资料库副本登录 CyberBus，开启并确认 | 已保存正文/附件不丢；旧 inbox/冲突/未完成投影如果阻止采用新 workspace，应明确要求先处理，不能清空这些数据绕过 |
| [ ] | UI-17 换账户 | A 退出后登录 C，B 仍为原账户 | A 默认暂停；两个账户设备互不可见，不能建立内容同步；本地既有笔记保留，向 C 合并前仍需明确确认 |
| [ ] | UI-18 Android | 独立 Android 安装登录同账户，改名、暂停发现、开启后 push/pull/both、强停重启 | Keystore 授权材料可恢复，设备 ID 不漂移，正文/PNG/文件完整；后台限制和断网给出真实结果 |
| [ ] | UI-19 异网络 | A 在局域网，B 用另一网络/热点，重复 UI-06～09 | 记录实际网络结果，发现或 relay 端口可达不能代替正文/附件落盘成功 |

## 结果记录模板

每例填写 `PASS / FAIL / BLOCKED / 未执行`。遇到第一个失败保留现场，可继续不依赖它的用例；不要删库或重新生成身份掩盖错误。

```text
用例编号：
结果：
源码提交 / 构建产物 / 构建日期：
A、B 系统与网络：
使用隔离资料库：是 / 否（不附私有绝对路径亦可）
前置条件、操作、预期、实际：
错误代码 / 操作阶段 / 大约耗时：
重启或明确重试后是否恢复：
截图或屏幕录像（遮盖账户标识与私人内容）：
```

更多协议与命令行边界对应 [验收矩阵](TEST-CASES.md)。用户手测结果回填本页或另附记录后，才可把原生 UI、移动平台与真实使用体验标为通过。
