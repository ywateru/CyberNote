## 建议范围

1. Mac 原生三栏列表的标题/数量共用现有零结果路径的纵向坐标：标题 y=11、数量 y=27。开场普通路径为 y=9/28，零结果已为 11/27。字体维持标题 13 semibold、数量 11，保留框高 18/15、textX/titleWidth、可见性、截断和对象身份。普通三栏与零结果共用纵向基线；零结果专有的水平 -1 保留。画廊与独立窗口缺少同等本轮测量，不扩展纵向改变。
2. 仅 Mac 原生普通列表的**第一个 `.note-entry` 所含日期标题**采用待验候选：font-size 15px、line-height 20px、height 40px、border-bottom .5px、padding-top 9px，维持左右 padding 16、weight 700 与原字体栈。使用结构选择器，不以“今天”文本硬编码。保留后续组 padding-top 19px/height 49px；保留移动端、非原生浏览器、宽屏 Android、画廊、独立窗口与搜索零结果规则。
3. 标题/数量纵向改变有直接同文、多状态证据。日期 15px 是有生产 WK 渲染机制依据的候选，**尚无既存“今天”15px 的同文真实 WK 结果证明**，必须在作者新候选上补同文 WK 渲染，再由实际应用截图验收。

## 已证事实与推导

完整标题两边墨迹高度均为 24px，开场克隆一致比原版高 4px；数量高度均为 20px，开场克隆一致比原版低 2px。沿用已存在的 11/27 逻辑坐标分别对应 +4/-2 截图像素，符合当前 2× 局部比例。这里是对开场帧与像素差的实施推导，没有量出原版 NSTextField 的内部 frame。06 旧分析使用标题前缀 ROI（y25/29），本轮包括中文全标题（y23/27），两者同为 4px 差，不能混用绝对上缘。

“今天”的左缘在每对状态一致；克隆为 60×29，原版为 57×28，克隆上缘 122、原版 130。原普通分隔线主要为 y183（中位灰 221），y182 为次暗行（241）；开场克隆 y180/181 两行等暗（222）。因此首组应单独调整字形尺度、行盒与边框，不平移整个滚动容器。39→40 逻辑像素会让首条笔记流布局起点下移 2 个截图像素；这也是新候选应检查的连带变化。

既存生产 WK 零结果 `clone-fill.jpg` 使用 15/20、padding-top9、height40、.5 边框组合，文字“备忘录”上缘 y130、分隔线 y183。它支持目标上缘与块底的渲染机制，但文字不同，不能当“今天”同文通过：本轮直接读该 ROI 时原版“备忘录”bbox [489,130,575,161)，克隆 [489,130,575,157)，并非字形高度完全相同。

历史 `typography-measurements.json` 中 headless Chrome 的 15/20 pad9 候选可以诊断方向，但 600/650/700 曾得到相同 SHA/像素；不能拿 Chrome 结果认证 WK 字重。原版标签的确切字体家族/字号未被本轮公开可读证据测出，不宣称原版字体就是 15pt。编辑器字体面板也不能证明工具栏/列表字体。

## 开场源结构与边界

开场 `toolbar.m` 的 `zeroSearchGeometry` 受 three/sidebar、搜索标题、count=0、有搜索值条件约束，原式标题 `zeroSearchGeometry?11:9`、数量 `zeroSearchGeometry?27:28`，水平 `titleX-(zeroSearchGeometry?1:0)`。建议仅让三栏纵向共用 11/27，不改变水平条件、titleRight/titleWidth、组布局、搜索编辑器、菜单、事件或数据。

开场 `App.tsx` 的 `.notes-scroll` 为 `listed.map` 生成 `.note-entry`，仅首条或分组改变时生成 `.date-section`。分组文本也可能是置顶、昨天、过去 7 天/30 天、年月；因此结构首项约束应覆盖实际首组，而非只匹配“今天”。原生顶部已用 52px 保留条移除 DOM notes-header。`.desktop` 并不独占 Mac（宽 Android 也可使用），需有现存 `.native-toolbar` 以及画廊/独立窗口排除。

开场普通日期规则为 16px、700、padding 7px 16px 13px、1px 边框、height39，无显式 line-height；后续组为 padding-top19/height49。移动端有自己的 21px/25px/auto/15px0 8 以及后组 22px0 9；画廊有单独边框/尺寸。候选应限定首组，保留这些路径。不要借本轮同时修改行高、摘要、预览、行间距或滚动容器。

## 实施后需要的有限复核

- 检查真实生产源码差异及 retained NSTextField 身份：纵向仅预期改变，textX/titleWidth/可见性等保持；现有零结果 11/27 不倒退，画廊与独立窗原基线保持。
- 用候选**真实 WK** 渲染同文“今天”，记录 bbox 宽/高/上缘与分隔线；检查首条流布局的预期 2px 下移。只比较 CSS 字符串或 Chrome fixture 不足。
- 检查 Mac 原生普通列表可见 228→隐藏→恢复→208→228，完整同文标题/共同副标题；保留有限笔记正文与状态。新安装应用的同条件 JPEG 是最终屏幕验收，暂不标像素 PASS。
- 检查结构首组为置顶/其他标签、无日期首项/空日期、后续“昨天”仍使用旧后组规则；确认移动、非原生、宽 Android、画廊、独立窗、零结果隔离。
- 不需要为 readiness 重跑旧 401 状态大审计。完整编辑器、数据、菜单、选择、搜索与持久化未纳入候选范围。
