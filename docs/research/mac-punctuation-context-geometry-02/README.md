# macOS 中文标点上下文控制样本测量 02

本组支持“连续中文标点存在上下文相关的累计位置差”的判断。三个明暗阈值下，连续 8 标点的 clone 可见行宽均比原版多 **61 个截图像素**；将同样的标点用“中”隔开后，17 字整行只多 **5/4/4 像素**。这不证明具体字体、字距 feature、排版 API 或缩放比例。

来源为 `docs/verification/mac-punctuation-context-runtime-02/` 的 original 01 与 clone baseline 02。两张均为 2786×1806 JPEG。父任务记录两边新建笔记、明确纯文本粘贴、Fill、正文聚焦和指针远离；本分析独立核对两份 AX 聚焦正文的完整值均与 corpus 完全相等。所有 5 份输入的尺寸与 SHA-256 写入 `result.json`，分析前后相同。本次没有另行核对运行进程、构建或包身份。

全部坐标是 JPEG 解码后的**图像像素**，左上原点；bbox 为 `[x0,y0,x1,y1)`，右/下边不包含。不是 CSS 像素、AppKit point、DPR 或真实基线。中性墨迹条件为 `299R+587G+114B < threshold×1000` 且 `max(R,G,B)−min(R,G,B)<25`，阈值 120/160/200。两张使用相同固定 ROI；不平移、配准、缩放、重采样、掩盖、补画或自动合并字形。

每个阈值下连续行均分出 8 个 x-run，间隔行均为 17 个，与已知无空格文本的 codepoint 数一致。已目视核对顺序对应。此处是已知 corpus 的有界关联，不是 OCR 或可通用于任意文本的字符分割。文末淡黄色插入光标保留在派生图中；测量条件仅筛选中性深色墨迹。

## 文件、限制与复核

- `analyze.py`：Pillow 分析及输入身份断言，可直接重跑；不安装依赖。
- `result.json`：五份输入身份、完整聚焦核对、固定 ROI、三阈值每字与每行数据。
- `original-body-native-crop.png`、`clone-body-native-crop.png`：相同 `[1200,155,1740,550)` 原尺寸裁剪。
- `context-rows-same-x-native-strips.png`：两张 `[1210,200,1700,270)` 原尺寸裁剪上下展示，维持各自相同 x 原点，仅用于目视核对，不是配准结果。
- `manifest.json`：除清单自身外全部新输出的大小及 SHA-256；aggregate 按完整相对路径字符串排序，将 UTF-8 `<sha256>  <relativePath>\n` 串接后计算。

JPEG 派生 PNG 不是无损原始取证，明暗阈值与抗锯齿会改变边界。图像尺寸相同不等于 DPR、屏幕原点、应用内容框和字号相同，不能据此宣布像素级通过。父任务提供的 system13 与普通 PingFangSC@13 总 advance 差 37.09766pt、system fallback `.PingFangUITextSC` 属于原因线索；本分析不调用 CoreText，也没有建立其与截图像素的换算关系，更没有证明某次 API 设置有效或无效。

本次仅写此新目录；未修改旧证据、产品、target/cache，未操作 GUI/REA，未提交。每个输出阶段均先检查至少 2 GiB 可用空间；包括清单在内保守限制全部新文件小于 2 MiB。
