## 来源与规则化

参考 `../analysis.md`、`../measurements.json`（d22a393），原图为 `references/mobile/frames-2s/frame-044.png`，224×480，SHA-256 `d4d51679c9be81ca39c18a326ba497028398b213e1e0e13ecbed316859af06f0`。原录屏已经保全，不在本目录复制或改动。

统一采用74×60 viewBox。原卡片低清边界高59–60、线中心存在约0.5–1像素量测误差；本次把各卡线中心规则化到同一原始坐标系，而不是复刻压缩造成的小数抖动：

- 横线固定x7–67。密横线7条，y7.5/15/22.5/30/37.5/45/52.5；中横线3条，y15/30/45；疏横线2条，y15/45。
- 网格统一x7–67、y7–51，中心框60×44。密8×6、中4×3、疏2×2完整格，均明确画出首末边线。疏单格30×22，不变成正方形。
- 每个资产的源卡框、按74×60映射后的原始线中心及规则化最大偏移均在 `selfcheck.json` 的 `sourceNormalization`，方便后续回查。水平线端点统一x7/67，相对原版约7–8px留白的变化也属于规则化。
- 0.45单位线宽、单色黑色alpha=1，仅是工程起点；原设备DPR、高清线宽、颜色和抗锯齿未知。资产透明区域不含白卡/圆角/阴影/选中/触摸区，联系表棋盘格和标签也不在SVG内。

## 自查方式与结果

`prepare.py`先生成显式line SVG，再使用现有 ImageMagick 7.1.2-29 的本地SVG渲染器生成592×480（8×）透明PNG，最后用已有Pillow检查和制作联系表。每张实际渲染均检查：

1. XML只有根svg、单色g和line，viewBox、黑色stroke、fill=none及显式不透明stroke符合约束。
2. XML线数量与预期一致；图像中按覆盖率聚类的水平/垂直线数量一致，包含外框，完整格数由线数减1得到。
3. 所有线端点在8×图的对应邻域有alpha；没有遗漏末边或被画布裁掉的端点。
4. 图像外侧至少4原始单位完全透明；所有可见像素的RGB都是黑色。SVG图案中心范围与四边留白记录在JSON。

六项资产全部通过。详见 `selfcheck.txt`、`selfcheck.json`、`renders/` 与 `contact-sheet.png`。已实际查看联系表，六种图案可见，首末边线、留白与长方形疏格符合上述几何。自查是本开发者有限检查，不是独立验收，也没有计算与原版截图的相似度或伪造像素通过。

渲染器曾在省略stroke-opacity时把继承值输出为0，产生透明空图；最终SVG显式使用`stroke-opacity="1"`后才通过实际alpha与数量检查。该显式值符合SVG默认不透明stroke语义，没有把空图当成功。渲染密度采用本机SVG的96dpi基准，768dpi得到8×；脚本硬校验输出尺寸。
