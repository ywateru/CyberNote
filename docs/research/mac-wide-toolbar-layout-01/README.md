# Mac 宽窗工具栏：最小弹性布局候选

2026-11-04。仅离线读取已保存截图、采集状态和 `toolbar.m`；没有产品修改、构建、测试、GUI、进程或设备操作。测量程序、输入身份及原始边缘读数见 `measure.py`、`measurements.json`。本文是下一轮实现的校准依据，不是 pixel PASS、原版内部 frame 或原版布局算法的证明。

## 源码中的最小改动位置与候选公式

只读冻结的 `plugins/tauri-plugin-notes-ui/macos/toolbar.m` 为 41189 字节，SHA `3697f58ab1b73e3d5a7a1cc5eabe2c14ce59d6ff6bcaf71609fed0f26e721b91`。本轮没有重新验证此源码与截图 executable 的构建映射；后续实现必须检查文件是否变化。

源码 `placeGroup`（319–326）将组放在 y8、高 36，并按组宽分配按钮。`widthFor`（328–336）计算新建 36、编辑四项 161、共享两项 80，基础组距 18/18、共享至搜索 16，溢出另计 10+36。全七项、无溢出时，除搜索外总占宽 **329**。`layout`（338 起）先从分栏确定 `start` 和 `available=w-start-8`，普通非画廊分支把所有余量给搜索，再按既有次序移入溢出并夹紧搜索（382–395），最后放置组（398–409）。

候选只限 `threeColumn && hasSearch && 七项均可见 && hidden.count==0`；搜索为真实输入控件且留有可用宽度。**先完整执行既有搜索最小宽度、drop 次序和溢出决策，再增加弹性留白**。对这个限定状态：

```text
searchNew = min(searchFinalExisting, cap)       // cap 约 325–326
spare = max(0, available - widthFor(finalVisible, searchNew, overflow))
newToEdit = 18 + spare/2
editToShare = 18 + spare/2
shareToSearch = 16
```

新增留白只用于两个现有 18 间隔，不能进入 drop 所用的宽度预算；`start`、右距、标题、分栏、按钮内容和 hit rect 宽度不随此项校准。初轮保留缺组、无搜索、已有任何溢出、独立笔记、galleryExpanded、galleryBrowse 的原分支。缺组时“等分两个间隔”本身欠定义，不能无证据推广。

## 下一轮应核对的具体风险

- **窄窗与溢出**：必须保持已有移除顺序、最小搜索宽度、右侧约束；全组不足空间或其他 hidden 动作出现时回到原逻辑。不能因新增空隙导致更多动作进入溢出。
- **输入连续性**：保留原 search、field editor 及其祖先实例，只改几何。源码 409–410 的注释已注明隐藏祖先会让 AppKit 放弃 field editor；拖动过 cap 阈值时要检查插入点、选区、中文 marked text 和横向滚动，不从截图推定通过。
- **菜单锚点与点击**：整组平移后核对共享、更多、附件等菜单锚点及实际点击。此候选不改组内按钮宽度，也不以图标墨迹替代点击框；本轮没有执行交互验收。
- **范围控制**：标题和新建起点不因弹性项变动；gallery 两分支、独立窗口、缺组和已有 overflow 没有本轮新证据。不同活动、禁用或材质状态下颜色不能用来反推几何参数。
- **验收证据**：在同查询、同窗口画布、同分栏、可核实焦点/活动状态下重采 325/326 候选；再取一个中间宽度与一组真正三栏窄窗。局部 JPEG 表面测量仍不构成像素级通过。
