## 待实现的数据与模块契约

实现者先把最终选择同步到 `docs/architecture.md` 和对应 UI 文档，再改生产代码。下面规定跨边界必须满足的条件，类型/命令名可在保持这些条件下调整。

### 文档投影与标签

编辑器文档为内容事实来源。定义共享的文档投影：`plainText`、标签集合、清单统计、内联笔记引用、可浏览媒体项。TS 与 Rust 的文本投影必须对新内联节点得到同样的可读文字；标题、摘要、搜索、导出不能丢掉数学结果或笔记链接，也不能把内部 ID 显示为正文。

标签需要显示文字与比较键的明确契约，区分 `#` 普通字符与已识别标签。至少支持已证实的中文样例和空格提交；其余字符、大小写/Unicode 规范化、粘贴/回退边界须明示，并补测后才宣称原版一致。可用 mark 或内联节点表示已提交标签；不能只把任意 `#` 命中当目录。派生目录由当前可见文档重建，保存/撤销/重做/删除/恢复后同步更新；若持久化索引，必须同事务维护并可重建，不能另存成为第二事实来源。

锁定契约须精确沿用现状：正文加密、密钥在进程内；标题目前是可见元数据，不能宣称标题隐藏。标签、数学、笔记引用来自正文，不能作为新的明文全局索引写出。未解锁笔记不参与内容派生，解锁后内存可计算，closeLocks 后清除。按锁定状态筛选可用公开元数据。当前含附件笔记不能锁定；本任务不得顺带取消这个限制却不实现附件加密。

### 智能文件夹是保存的查询视图

建议把普通/系统/智能文件夹改为显式联合类型。智能分支持有有版本的 `SmartQuery { version, combine: all | any, rules: SmartRule[] }`；普通/系统分支不得携带规则。规则使用带 `kind` 的联合类型，校验参数，不存含义不明的任意 JSON。

| 规则组 | 必须明确保存的输入 | 不能凭菜单推断的语义 |
|---|---|---|
| 标签 | allSelected/anySelected/anyTag/noTags；有选中项的模式保存规范化标签键 | 空选择、多选切换、大小写规则 |
| 日期 | created/updated、条件、UTC 时间或日历范围、范围解释所用时区 | “最近3个月”不能静默变90天；边界、相对范围、夏令时需明确 |
| 清单 | any/unchecked/checked/none | 同篇含勾选和未勾选是否同时命中、嵌套清单 |
| 附件 | any/photoVideo/scan/drawing/map/website/audio/document/none | 语义来源不能只靠文件扩展名冒认 |
| 文件夹 | include/exclude 与稳定 folder ID 集合 | 是否递归子目录、多目录组合 |
| 置顶/快速/锁定 | 明确的包含/不包含条件 | 快速/锁定的未采样控件与创建后结果 |

共享和 @提及不属于本地可成立的协作数据，不能创建假状态。UI 如何表达本地不可用须与现有菜单规范一致，并明确记录差异。未取证语义先作为工程决策登记并补证；不应靠静默返回空列表掩盖未知规则。

智能文件夹不拥有实体笔记：创建/编辑只保存查询，不改变任何 `Note.folderId`；新建笔记不能把 smart ID 当物理目录。视图默认如何处理最近删除、搜索叠加、目标普通目录、删除智能文件夹等需在实施前明确。建议查询排除最近删除，但这是工程建议，尚非该次原版实测。规则校验失败保持原规则和旧列表；更新后保存、重启后重新求值，不保存一次性匹配结果充当智能文件夹。

### 数学与链接

`MathMode = insert | suggest | off` 放入有类型设置，缺省策略明确且归档验证同样检查；本机原版当前值是 suggest，不足以推断所有新安装默认值。建议态属于编辑器临时状态，绑定 note ID、表达式范围和文档版本；取消、改式、切笔记、组合输入时失效，不能先保存为已接受结果。接受后持久节点需分别保存 `expression`、`result` 和可解释的求值版本；Return 接受是一笔历史事务，不产生换行；重新编辑来源后重新计算或明确显示错误。

安全求值只解析已声明的有限算术语法，不运行 JavaScript/Rust 用户代码。初次至少满足 `2+3=`；其他运算、精度、除零、超限和不支持语法明确给出行为，不能把错误变成0或旧结果。插入模式何时自动确认须补采原版；Off 不产生新建议，已存在节点如何保留须作为实现契约验证。

笔记链接使用 `noteLink { targetNoteId, labelPolicy, ... }` 的专用内联节点/标记，目标身份不依赖标题。显示策略（固定标签或跟随标题）需补采并记录；链接生命周期区分正常、缺失/删除、锁定目标。普通 URL 继续使用独立 link mark 和安全的系统打开边界，不能将 URL 与笔记 ID 混用。

```text
>> 输入 → 当前可见笔记检索 → 键盘/点选 → 单事务替换输入
  → saveDoc → 每笔记队列 → Rust saveNote → SQLite
点击 noteLink → 校验目标 → 等待源笔记保存成功 → chooseNote 同窗入口
  → 目标 Editor → 通过已证实的导航入口返回源笔记及必要上下文
```

当前 `flush()` 等队列结束，但 `saveDoc` 在队列内部 catch 并经 fail 展示错误；仅 `await flush()` 不足以证明源笔记保存成功。链接导航须检查未保存/失败状态，不能失写后仍跳走。选择目标后既有移动布局/画廊上下文同样正确，不起第二编辑器数据源。缺失目标给明确结果；锁定目标走原有解锁流程，建议列表不可暴露受保护正文。

### 标准格式与类型浏览

完整归档保留所有格式、设置和受管字节；标准 Markdown/PDF 用于交换可读副本，不能用 `.notesbackup` 改扩展名实现。定义 `ImportPlan`：格式/文件来源、已验证文档、待提交受管资源、格式损失/错误。文本和 Markdown 解析先进入当前文档 schema，再与资源一起提交。Markdown 相对附件路径只从用户选定的受控来源树解析，阻止越界，不自动取远程 URL；缺失资源明确报错或在用户可见的导入预检中说明，不能悄悄删掉。

Markdown 导出定义文字/清单/表格/URL/内联数学/笔记链接/绘画/附件的映射和损失边界；原版附件目录格式未采样前不声称兼容。PDF 必须产生能打开的真实文件，验证分页、中文、表格与媒体表示。已锁定内容需要显式解锁并沿用导出权限契约；不能把空占位文档导出成功。取消、写入失败和解析失败保持旧工作区/旧目标，资源发布复用 FIX-00 的暂存与一致性原则。

附件浏览复用 APP-002 的受管文件与预览，不再另造一套媒体读取。类型投影可返回 `BrowseItem { noteId, source: attachment | drawing | structured, sourceId/position, category, displayName }`；位置/ID须在文档变化后校验。photoVideo/audio/document 可由已验证 MIME 区分；scan 需要 APP-004 的真实扫描来源，drawing 取文档节点；map/website 仅在存在结构化来源时出现，不能把普通图片命名扫描件或普通 href 命名网站附件。分类“无附件”和智能规则必须使用同一投影。

类型目录 → 真实项目 → 所属笔记同窗选择/定位 → APP-002 预览，是一个完整链路。浏览范围、空态、删除/锁定过滤和原版布局还需取证，现有“当前笔记附件”弹窗不算全局浏览完成。APP-004 未完成前 scan 项保持真实空或不可用；不能用合成扫描条目验收该类别。
