## 输入与内容边界

只读取 `docs/verification/mac-body-vertical-runtime-03/` 中的 `06-original-long.cua-image`、`06-original-long.ax.txt`、`07-body03-long.cua-image`、`07-body03-long.ax.txt`、`long-corpus.txt`，所有 5 个输入的字节数和 SHA-256 已记录在 `result.json`，测量前后及最终复核均不变。未修改刚完成的短正文报告、冻结语料、产品、构建或根验证清单，未执行 GUI、ADB 或运行时操作。此次未独立检查候选应用包或新增运行进程身份。

两图实际均为 **JPEG、RGB、2788 × 1806**。语料为 339 个 Unicode 码点、833 字节 UTF-8，末尾有 1 个 LF。逻辑行从 0 起：标题为 0，首组 10 个 Ag中文 为 1–10，连续两个空段为 11–12，第二组 10 个为 13–22，207 个码点的长段为 23；语料最终 LF 后存在字符串空尾元素。

AX 正文提取采用明确边界：从目标正文节点 `Value: ` 后起，至下一节点声明前的 `\n\t+节点号 ` 为止，排除该 1 个结构性换行。原版下一节点为 114 滚动条，候选为 28 text。这样提取后，原版正文为 339 个码点、尾部 1 个 LF，与语料完全相同；候选为 340 个码点、尾部 2 个 LF，比原版及语料多 1 个 LF。去除尾 LF 后正文相同，不能报原始 AX 全文完全相等。提取末端的原始边界字符串在 JSON 中保留。AX 序列化尾换行本身不足以证明编辑器真实空段数量或段落框位置。

原版 AX 显示列表 row 47 被选择，没有正文聚焦声明；候选 AX 焦点为 node 2 `HTML content`，并非正文声明。候选长段后可见金色插入光标，此可见状态不覆盖 AX 的焦点记录。两图指针及光圈均在列表选中项，未进入正文 ROI。

## 布局条件与测量方法

两图保持采集时的分栏状态。侧栏边界目视约为原版 x=456、候选 x=546；在 `[1168,1200,1280,1600)` 内以列平均灰度 <240 重新测得正文左分隔线原版 `[1176,1178)`、候选 `[1267,1269)`，候选右移 **91**。阈值 160 的标题墨迹左缘距各自分隔线起点均为 50。相同画布不代表相同正文布局框；未测得真正正文右边界或独立滚动偏移。原版滚动条 AX 值为 0，全文也可见，这仍不能证明两边布局框相同。

所有结果为原始解码图像像素，左上原点，边界框 `[x0,y0,x1,y1)`，右边及下边不包含在框内；不换算为 DPR、AppKit 点或 CSS 像素，不把墨迹顶部称为真实基线。中性墨迹条件为 `299R + 587G + 114B < threshold × 1000` 且 `max(R,G,B) − min(R,G,B) < 25`，分别计算 **120 / 160 / 200**。

横向 ROI 为原版 `[1210,2760)`、候选 `[1300,2760)`，使用记录于 JSON 的共同固定 y 条带隔离各行。没有移动、缩放或配准原图；放大裁剪只用于人工读换行，边界框一律从原始图像计算。下面列出阈值 160；JSON 保存全部三个阈值的逐行框、尺寸、差值和行映射。
