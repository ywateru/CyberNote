## 坐标、裁切和换算

下表全是**原图像素**，左上原点，矩形为`[x0,y0,x1,y1)`；不是pt、dp或CSS像素。墨迹、金色和近白填充的阈值/有限ROI均见[measurements.json](measurements.json)，可按记录的逐像素谓词重算。图像有压缩和抗锯齿，阈值bbox不是原生控件frame；原版外边缘一般保留约±1–2原视频像素的不确定性。

安卓状态栏为`[0,0,1080,83)`，底部三键导航栏为`[0,2148,1080,2280)`；可见应用裁切为`[0,83,1080,2148)`，高2065像素。原版顶端状态信息和底部home indicator也属于系统区域，但本视频不足以量出物理safe-area边界。本研究仅约定排除顶部`[0,0,224,28)`和底部`[0,466,224,480)`，保留`[0,28,224,466)`作辅助比较；这不是测得的原版逻辑viewport。底部home indicator墨迹约在`[73,473,152,476)`。

唯一比例辅助是宽度比`s=1080/224=4.8214285714`，将安卓尺寸除以s后与原视频像素比较。若需顶锚辅助坐标，可用`x_a=s*x_o; y_a=83+s*(y_o-28)`，但原版辅助裁切按宽度放大后高2111.79像素，与安卓2065像素仍相差46.79像素；不能同时强行贴齐顶底、拉伸纵向或用这一变换宣称整图零差。底栏改按自己的顶边比较内部几何。

## 新包同屏复验的有限入口

新包应另存自己的APK身份、设备截图和系统栏边界，打开未滚动的展开文件夹页，关闭键盘/搜索/菜单/编辑态，再重新量以上ROI。若截图尺寸或系统栏改变，重新记录边界，不能沿用旧坐标作为已测结果。

先核对标题墨迹、搜索框、第一张卡片上边与左右边、共同单行pitch、同名快速备忘录文字左起点，再独立核对底栏两个图标的金色bbox/中心与图形。原版两条额外首组行没有本地对应内容时，第二组只比侧边距和单行内部几何；待有真正相同内容状态再比较跨组纵向节奏。本研究不补定卡片圆角半径、字体基线、系统安全区或动画曲线，也不涉及智能文件夹表单。

图像输出均为派生标注，未覆盖来源：[原版原尺寸标注](original14-native-guide.png)、[安卓原尺寸标注](android-native-guide.png)。编号1–10依次对应标题、搜索、首卡、第二卡可见部分、快速文字、备忘录文字、快速图标、备忘录图标、底栏左图标、底栏新建图标。另有[标题搜索4倍近邻局部图](original14-title-search-nearest4x.png)、[快速行4倍近邻局部图](original14-quick-row-nearest4x.png)、[底栏4倍近邻局部图](original14-footer-nearest4x.png)，只为看清原始压缩像素；所有数值仍从未放大的原图计算。

完整输入哈希、源帧校验、ROI、逐通道阈值、原坐标、宽度换算及分隔线原始采样均在[measurements.json](measurements.json)。本轮结论仅是后续校准入口；没有新包设备复验、整体像素一致或总体交付完成的结论。
