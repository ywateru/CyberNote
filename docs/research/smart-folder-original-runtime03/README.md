## root操作过程

起始IN-A为任意(包含A,包含置顶)，A-PIN和A-PLAIN两条，PIN计数1。打开编辑定义，在同一文件夹输入行通过真实候选键盘选择加入B token；改名MULTI-AB并保存，三条结果A-PIN/A-PLAIN/B-PLAIN。没有把自由输入字符串伪记成token成功。随后将物理B样本置顶，PIN计数2，恢复单A的目录条件并观察任意组合仍得三条。打开新规则类型菜单时，已有文件夹规则使第二行的“文件夹”禁用。

改“全部”的前两次尝试没有实际保存到预期状态；09文件名and-one-result和10的and-settled都仍是三条，原始文件未覆盖。之后明确打开全局规则菜单、选择全部并Return保存，11才只得A-PIN。再将目录改不包含A并以全部+置顶保存，12定义与13结果只B相符。

对B打开上下文“移到”菜单，仅检查目标启用状态，没有移动。14截图只有父菜单，目标子菜单禁用事实来自完整AX：智能IN-A/PIN存在但禁用，当前物理B也禁用，物理A/A1可选。随后在智能结果取消B的置顶，root观察主视图自动回到物理B，正文仍相同，智能计数0、PIN1；15保存结果端点，不冒充逐事件追踪或不同作者独立重放。

收尾恢复原名IN-A、任意、文件夹包含A、置顶包含；16记录恢复定义且包含菜单仍展开，继续Return保存后17再次得A-PIN/A-PLAIN两条，PIN1。B取消置顶的直接状态在15；17计数与之相符。没有永久删除定义或物理目录，没有冷重启或修改其他私人笔记。

## 证据限制

原版打开编辑表单时曾出现CUA零尺寸捕获错误，实际动作已经打开窗口；同一绑定再观察得到成功表单，不因此重启应用。09/10失败的具体原因未证明，不能称原版AND逻辑错误或异步bug。末匹配取消后的自动导航只限此样本路径，独核仅验证端点。图像是JPEG，四张表单1368×636、其余主窗口2788×1806；不混算尺寸，不授予原生无损或像素通过。

本轮补证支持多目录token联合、A外置顶的任意/全部、排除A、改名保存及智能移动目标禁用。定义删除、引用物理目录删除、冷启、其他过滤器、手机表单和全部编辑失配导航仍未知。需求事实更新到 `docs/ui/local-features.md`；Rust查询/存储/归档/权限接入尚待实施，准备在同级 `smart-folder-implementation-readiness03.md`。
