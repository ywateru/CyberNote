# CyberNote 启动加载

2026-11-07 实现于当前源码，未重新生成 macOS / Android 安装包。

首屏直接显示现有 SVG Logo，保留方形双眼。金色细线沿六边形轮廓匀速游走，双眼边缘轻微呼吸，周期 2.8 秒。Logo 下显示 CyberNote 与“正在打开备忘录…”。背景直接消费当前主题 `--paper`；Classic 浅色为 `#ffffff`、深色为 `#1e1e20`，不再维护独立启动色。桌面 Logo 为 104px，移动端为 88px。

## 启动与交接

- HTML 已包含加载画面，CSS 和独立恢复脚本在应用入口之前加载，覆盖 React 与主脚本初始化时间。
- 初次可信工作区读取完成后，恢复选中文件夹和备忘录、准备可见编辑器；macOS 再绑定原生工具栏，避免先用空工作区显示工具栏。
- 主界面提交完成后等待两个绘制帧，再用 220ms 淡出交接；没有人为增加最短等待时间，也没有模拟进度百分比。
- 加载期间主界面根节点保持 inert，屏幕阅读器只读取加载状态；交接完成后恢复主界面交互和可访问性。
- 此画面只创建一次；切换备忘录、同步、打开设置不重建它。

## 外观与恢复

外观默认跟随系统；本地仅缓存最近一次成功读取的主题偏好，供下次首屏使用，不缓存笔记内容。启用“减少动态效果”时停止循环动画并立即完成交接。

工作区初次读取失败、应用入口资源加载失败或启动期间发生未捕获错误，均停止动画并提供“重新加载”。超过 15 秒仍在加载时显示耗时提示和重新加载入口，后续正常加载成功仍可继续进入主界面。

## 验证

`pnpm build` 通过。`pnpm test:startup` 在隔离合成工作区运行，桌面 19 项、移动 4 项通过，覆盖脚本等待前首屏、SVG 实际动画、React 之前的 Android 系统栏投影、原生工具栏投影、工作区慢加载、错误与重新加载、空工作区、笔记切换、设置、深浅外观及减少动态效果。Android 9 调试包真机已确认启动后首页上下系统栏为 `#f2f2f7`，编辑页为 `#ffffff`；启动脚本在 `.app` 挂载后停止投影，避免覆盖 React 页面。

证据位于 `artifacts/startup/`。原生工具栏验证使用模拟 IPC，不代表重新构建或运行了 AppKit / Android 安装包。

## evolve114 外观首屏

head 在应用入口之前加载注册色板生成的 `src/themes/tokens.css`，启动表面直接使用 `--paper/--ink/--secondary/--accent`，不再有一套独立明暗色值。`public/startup.js` 独立校验三字段 AppearanceV2 缓存，设置 `data-theme-id` / `data-theme` / `data-scheme` 和兼容 `.dark`；跟随系统时订阅 media 变化。入口失败仍显示相同主题的重载入口，root 保持 inert。启动脚本同时把 `.startup` 的实际纸面投影到 Android 顶部状态栏和底部导航/手势区；React 接管后由页面投影重新取色，启动脚本检测到 `.app` 后停止投影，避免把纸面色写回已进入的页面。宿主尚未收到 JS 投影时，`MainActivity` 使用日/夜纸面 `system_bar_fallback` 覆盖首帧，避免窗口默认粉白色带。

缓存键 `cybernote.startup-appearance-v2` 只保存已确认外观，无正文/账号资料；仅无新缓存时兼容旧明暗缓存。非法缓存不会破坏启动，回退 Classic/system。App 等 workspace 权威设置加载完成后校正缓存；设置保存失败不提前应用或缓存。浏览器 bridge 调用只能证明启动页取色与调用顺序；Android 9 调试包已确认启动后页面系统栏采样，原生发布包冷启动首帧、系统图标和三键导航仍须在准确 Android 设备上验收。
