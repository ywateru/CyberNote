## 新建：层次与默认值

主窗口上方显示圆角表单，背景主窗口变暗；表单标题、名称和规则区从上到下排列。下图表示区域顺序，不是按字符换算尺寸。

```text
主窗口（表单打开时背景变暗）
  +-------------------------------------------------------------------+
  | 新建智能文件夹                                                    |
  |                                                                   |
  | 名称： [新建智能文件夹___________________________________________] |
  |                                                                   |
  | [勾选] 制作智能文件夹                                              |
  |        使用标签和其他过滤方式整理。                                |
  |                                                                   |
  | 包含匹配下列 [全部 v] 过滤条件的备忘录：                            |
  | ----------------------------------------------------------------- |
  | [标签 v] [所有已选 v] [标签 token 输入________________] [-禁用] [+] |
  | ----------------------------------------------------------------- |
  |                                                   [取消]   [好]   |
  +-------------------------------------------------------------------+
```

从“添加文件夹”进入时，S2-01 首先是“新建文件夹”，复选框未选，仅名称、说明及取消/好；勾选后才展开上图。默认一条标签规则、组合为“全部”、模式为“所有已选”，token 为空；旧采样的默认名称被选中可编辑。S5-01 已输入合成名称，焦点在名称框，不能据此规定每次切换规则都夺回名称焦点。

可见样式：白/浅色表单，粗体标题，灰色说明；弹出选择器为浅灰底。名称或 token 聚焦时有黄色焦点环；“好”为黄色主要按钮，“取消”为灰色按钮。规则区由水平分隔线界定，右侧圆形减号/加号；禁用减号更淡。字体、颜色、圆角及间距的准确数值待测，不从视觉印象写死为原版数值。（S1、S2-05、S5-01/04/05）

| 控件 | 已见行为与实现要求 | 来源 |
| --- | --- | --- |
| 顶部组合 | 文案“全部 / 任意”；控制整组规则，不放在每条行内。两种均有实际保存的有限样本。 | S2-15–18、S3-11 |
| 类型选择 | 按顺序列出：标签、创建日期、编辑日期、共享、@提及、核对清单、附件、文件夹、快速备忘录、置顶备忘录、锁定备忘录。已观察菜单不等于各类型已实现。 | S1 |
| 增减规则 | 每行右侧减号、加号。仅一条时减号禁用；多条样本中减号可用。S7已有标签时两次新增均为创建日期／今天；从第一标签行新增时实际图片插在该行之后、原置顶行之前。规则总数上限及任意行删除后的焦点待证。 | S2-12、S3-06、S5-01、S7-02/05 |

| 目录候选弹层 | 从 token 输入框下缘展开，覆盖其下规则/底部区域，带目录图标和名称。QA 前缀当前可见 A/A1/B，已有 IN-A/PIN 不出现；仅限该前缀样本，不外推全部系统目录。 | S4-03 截图；AX未完整表达候选 |
| 置顶备忘录 | 类型旁是“包含 / 不包含”，没有目录 token 输入；单条和与文件夹组合均有保存定义。 | S2-12/15/17、S4-02 |

标签行按模式切换控件，token 输入不能只做不可见占位框：

```text
所有已选 / 任何已选：
  [标签 v] [所选模式 v] [标签 token 输入______________] [-] [+]

任何标签 / 仅不含标签的备忘录：
  [标签 v] [所选模式 v]                                 [-] [+]
```

| 标签模式 | 输入控件 | 本轮已证保存边界 |
| --- | --- | --- |
| 所有已选 | 显示 token 输入 | 空输入点击“好”必须警告，不保存；选择非空标签后的实际求值待证。 |
| 任何已选 | 显示 token 输入 | 同上；不能将空选择解释为无匹配的合法定义。 |
| 任何标签 | 不显示 token 输入 | 只验证了控件隐藏，未实际提交此模式，保存和成员求值待证。 |
| 仅不含标签的备忘录 | 不显示 token 输入 | 同上。 |

四种模式文字来自 S1；隐藏与拒绝来自 S5。S6实际输入UI时显示“创建新标签 ‘UI’”及既有#UI对照候选，下拉浮层未在AX中列行；Down两次/Return选择既有标签形成胶囊。allSelected→anyTag→allSelected的本次草稿往返保留该token，anyTag下AX仍有disabled输入但图片不可见。新标签创建持久化、其他模式往返、胶囊箭头菜单和完整键盘行为仍待证。

## 空标签警告、取消与保存

空“所有已选 / 任何已选”时，表单“好”仍可点击，验证发生在提交动作后。必须显示独立警告层，不把此状态替换成提前禁用“好”或静默保存空查询。

```text
草稿表单（尚未保存）
  +---------------------------------------------------+
  | “标签”过滤条件不完整                              |
  |                                                   |
  | 必须为“标签”过滤条件选择至少一个标签。             |
  |                                                   |
  |                     [ 好 ]                        |
  +---------------------------------------------------+
```

警告标题加粗，正文在其下，底部单个黄色宽按钮“好”；实际换行依容器宽度，不能从 ASCII 强制换行。S5-02/03 的 AX 焦点为警告表单。确认警告后继续同一草稿并可改模式，未创建新目录；名称不因验证失败重置。（S5-01–05）

| 输入/动作 | 已见结果与落地约束 |
| --- | --- |
| 表单“取消” | 新建草稿退出，无新侧栏实体（S2-05/06、S5-06）；编辑草稿取消，重新打开仍为原定义（S4-03–05）。取消不得提交草稿。 |
| 表单“好” | 对完整且已支持的规则提交定义；原版已有置顶、文件夹及组合实际保存样本，后续结果和重开定义可核对。保存结果与计数/列表必须来自同一定义；具体工程保存接口归共享契约。 |
| 空标签“好” | 显示上述警告，保存拒绝，仍是未提交草稿（S5-02/03）。 |
| 警告“好” | 关闭警告后继续草稿（S5过程），不当成第二次确认保存。 |
| Return | S3记录过组合编辑后Return成功保存；候选/菜单展开时的Return作用随焦点而异，不绑定全局无条件提交。 |
| Escape / Tab / 点击表单外部 | S4曾用Escape退出目录候选；表单Escape取消、Tab完整顺序、点击外部是否可关闭均待证。 |

S7只在未提交草稿中观察创建日期／今天，不作为日期查询保存或求值证据。本批仅草稿显示该状态，若能力尚未支持，提交须说明并保留草稿；不得忽略该行伪保存。完整原版其他规则与用尽类型后的新增行为仍待实现及补证。

后端保存失败、加载中、忙碌和跨窗口定义冲突的原版画面未取证。工程须保留失败草稿并等待真实提交结果；这项防丢要求来自实现需要，其提示样式不得宣称已与原版一致。不要为尚无后端求值能力的类型提供一个看似可成功保存的入口。

## 尺寸与待证边界

[三行规则测量12](../research/smart-folder-rule-add-measurements12.md)给出S7-05单层规则的84原图px行节奏、48px选择器与加减视觉中心高约13px的有限参考；与[公共表单测量09](../research/smart-folder-form-measurements09/README.md)共同使用。鼠标遮挡区域已排除，数字不直接换成CSS/pt，目录token双层行不能套用84px。

本文只规定可见区域、排列与条件显示，没有将 JPEG 像素换算为 pt，也没有输出精确字体/间距/颜色常量。现存记录包含表单近景和带主窗口的捕获，两者比例不同，不能按截图外框当同一原生表单尺寸。后续像素校准需明确捕获范围、原始像素、显示缩放，再独立测量；当前无“零差”结论。

窄窗口、长名称/大量 token 的换行滚动、规则很多时的高度限制、深色/hover/按下态、空名称警告、最后 token/规则处理、被引用目录删除、智能定义删除均待证。手机页面另行以手机证据定义，不复用本页作为原版手机外观证明。


## 普通新建几何补证15

[固定原图研究14](../research/mac-smart-u-native-geometry14/README.md)区分普通800×414与智能1368×586原像素表单，不得把普通表单撑到智能宽度。普通底部需水平分隔线，按钮160×48、间隙16、右/下40原图像素。实现前在实际运行引擎证明截图像素和布局单位映射；[geometry15](../plan/tasks/app-mac-folder-form-geometry15.md)仅普通Mac表单改动，不把离屏受控渲染当实际包像素通过。普通→智能根据实际草稿状态切换布局，名称/取消/提交契约保持，错误和窄窗不得裁切。

重开智能定义时，置顶“不包含”必须按持久value:false回填草稿pinned:false，不能套newTagRule的默认true。Android05实测揭示共享映射缺陷，见[hydration16](../plan/tasks/app-smart-draft-hydration16.md)；Mac虽然未在本批操作false，仍受共享源码问题约束，不授完整编辑通过。
