# 手机正文中的已保存录音卡片

## 2026-11-08 交互更新

按用户最新标注，手机保存后的录音卡固定显示波形和总时长。波形直接拖动定位，播放/暂停仍由真实媒体控制器处理；点击或双击标题、卡片不再展开旧的进度条及前后15秒区域。桌面仍保留展开控制。

波形来自实际音频解码，沿用5分钟、8MiB的解码上限；未知时长、超出上限或解码失败时保留中性轨道，不生成假波形。媒体尚未就绪时定位禁用，真实读取错误与重试入口保留。切换附件或权限变化继续释放解码和媒体资源。

底部工具栏在浏览和编辑状态都提供麦克风入口，复用原有录音会话与保存流程。320px编辑工具栏保留7个44px触点。格式面板打开后，正文点击、选区变化、保存及窗口失焦不会关闭面板；新选区同步到格式操作目标，面板内状态跨保存保留。关闭按钮、Escape或Android返回键可明确关闭；离开笔记仍清理原目标。

受控真实App/Editor检查：`pnpm test:mobile-editor`。覆盖波形解码、真实seek与播放、点击不展开、更新选区后连续格式设置、保存不重挂面板、显式关闭、两个麦克风入口、窄屏触点及桌面原交互。结果保存在`artifacts/mobile-editor-interactions/`，不将受控媒体源视为真机麦克风验收。

以下为原有录屏研究和历史候选记录；当前交互以上述用户更新为准。

此页只约束保存后卡片；录制面板见 [recording-mobile.md](recording-mobile.md)。证据为已保全用户录屏，具体源帧、原比例裁剪、克隆差异与限制见 [保存后卡片研究](../research/mobile-saved-audio-card-20261104-01/README.md)。224×480 有损原片不能证明高清像素、原生点数、字体或圆角精确值。

## 整体结构与区域

```text
笔记正文（保存后的 attachment 节点）
┌───────────────────────────────────┐
│ 新录音                             │
│ 2026年11月3日 10:26     [▶ 播放]   │
│ 音频 · 2秒                        │
└───────────────────────────────────┘
后续正文／表格
```

上述日期和2秒仅是原片实例，不是可硬编码的默认值。原版 n1065/35.5秒已显示灰色圆角紧凑卡，左侧三行、右侧白色播放胶囊；标题粗于两行次级信息。卡片跟随正文滚动。日期属于卡片内部，不能拿页面顶部的笔记日期代替。

标题和音频必须来自实际已保存附件。日期来源以架构“保存后录音日期与紧凑卡片”为准：本次录音首次实际开始的应用观察点，保存可选UTC毫秒并在显示时用设备本地时区生成年月日HH:mm。APP-002-AUDIO-CARD-01源码候选已把可选recordedAt接入完成结果、票据、附件日记/公开行、同权限读取与归档1/2，开发检查结果见`../verification/app-002-audio-card-01/README.md`；仍待独立审查与安装版验证。没有事实来源时省略该行，不能用当前时间、笔记创建/修改时间、文件mtime或截图文字补造。原版日期取录制开始、结束还是保存时刻尚未实证。

原片的紧凑时长为“音频 · 2秒”，而录制面板暂停值为00:02.60。它支持短时长中文秒数这一可见形式，不足以证明长录音格式、小时边界、所有舍入规则或文件精确时长。卡片总时长与播放器当前进度是不同显示上下文；不能为改卡片而全局修改已有transport的mm:ss表达。

## 输入、状态与未知范围

卡内播放按钮的存在已证实，保存后实际触点与回放流程未取证。原片所检帧未见该卡展开、暂停、结束、拖动进度、±15、波形或卡片菜单，不能据此断言不支持这些能力，也不能把录制面板的控件移用为已保存卡片目标。

当前克隆的紧凑/展开、真实播放/暂停/前后15秒/进度与错误重试属于已实现工程能力，其有限运行结果按candidate04报告保存；原版相同手势和展开外观仍unknown。紧凑外观校准不得顺带重写媒体controller、源身份、异步清理、操作重试、正文ACK或选区/键盘保护。

需要独立覆盖真实标题、非零时长、未知/加载时长、缺失日期、实际读取/播放错误、重复长标题、深色和窄屏。除已见亮色紧凑层级外，其他原版视觉目标均待补证；工程错误状态必须显示真实错误并可重试，不能用静态正常卡掩盖失败。

## 响应与尺寸边界

原帧紧凑卡裁切约188×42源像素，仅代表有损画面的可见边缘。此值和克隆1080×2280屏幕中的949×163卡片不是相同DPR或内容，不能直接相减作为CSS改动量。后续候选可比较卡片相对正文宽度、三行层级和按钮位置，必须标注重采样；原图、文字和控件边缘不得整体遮罩以制造像素通过。

Mac共用AudioPlayer时应另行核对桌面行为，不把本页手机证据作为Mac设计规范。手机未采样的深色、展开和菜单状态继续保留unknown。

## 源码候选布局与状态

手机布局只在`@media (max-width:760px)`且`.mobile`内应用。以下为工程候选，原片不足以测量精确CSS尺寸、字形、圆角和高度。

```text
已知日期                         日期未知（旧行／外部文件）
┌─────────────────────────────┐  ┌─────────────────────────────┐
│ 实际标题（单行省略）           │  │ 实际标题（单行省略）           │
│ 本地年月日 HH:mm   [▶ 播放] │  │ 音频 · N秒        [▶ 播放] │
│ 音频 · N秒                  │  └─────────────────────────────┘
└─────────────────────────────┘
读取未完成：暂显标题与“音频”，没有旧ID日期；读取失败：显示实际错误。
```

候选使用标题15px/19px行高、日期及总时长12px/16px行高、summary内距12px及左右gap12px。标题和两行次级信息单行省略；右侧白胶囊沿用原控件和44px触点。开发实际组件检查在320/390 CSS px下观察到三行卡高81px、标题不覆盖播放；这些是候选自身测量，不能作为原版误差或像素通过。Mac日期和手机总时长节点隐藏，原“录音 · mm:ss”行保留。

未知时长显示“音频”；0至不足60秒向下取整为“音频 · N秒”；60秒以上暂用既有mm:ss总时长。当前进度、拖动、±15和播放controller没有改动。换ID后新组件读取期间不保留旧日期，晚响应、失败、卸载、在途访问失效均拒绝显示旧值；这些开发检查使用受控媒体事件与实际Rust临时Store，不证明麦克风、编码或原生WebView播放。

## 组件与入口

```text
真实录音完成
  → 原AttachmentSubmission与Rust持久操作
  → 正文ACK确认attachment引用
  → Editor MediaView读取受管媒体及真实元数据
  → AudioPlayer紧凑卡
       ├ 标题／真实日期／总时长
       ├ 原有播放controller
       └ 原有错误与重试
```

文件导入音频不自动成为本机录音，不能从文件mtime宣称其录制日期。新增录音日期如果需要扩展持久元数据，必须同步保存重试身份、受管读取、归档验证与重映射、旧文档/旧归档加载和冷启；纯CSS任务不得暗加这些语义。
