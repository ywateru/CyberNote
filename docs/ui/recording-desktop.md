## 暂停/关闭自动保存64（用户最新要求）

用户反馈Mac录音中关闭后无法保存，要求“暂停或者关闭录音窗口，自动保存”。本节覆盖下方早期“暂停只试听/仅完成时提交”的规则，手机原现场不操作。暂停自动发布完整可播放累计音频及原A正文，确认后窗口保留且可继续；后续暂停继续累计，用户只看到同一张逻辑录音卡。关闭（系统窗口、×、Escape、owner转发及明确退出）保存最新音频和原A正文，准确final确认才销毁；失败保留窗口与字节供重试。

```text
录制 → 暂停/封存完整分段 → 累计合法音频 → 自动保存中 → 已保存暂停
  ↑                                                    │
  └──────────────── 同会话继续新分段 ───────────────────┘
有音频状态 → 关闭意图 → 排空/完成最新保存 → final ACK → 关闭
                                    └失败→保留窗口和音频，可重试
```

桌面采用完整分段生成有界累计WAV，不把非终结requestData前缀当可靠媒体。当前工程格式为24kHz单声道16bit PCM、100MiB含头（约36分24秒），并非原版压缩编码或无限时长；保存中可短暂禁用录音继续/试听，Notes其他操作仍可用，Close必须记录并随后执行。每次是不可变版本，复用附件journal；首次A映射书签插入，后续原位替换前一确认卡，保留最新A正文、选区和B操作。旧版在被替换前query确认committed，保留供Undo/历史引用；内部物理ID随版本变化，逻辑录音与开始日期不变。多版本增加本地及归档空间，错误明确不截断。checkpoint ACK保留会话，final ACK才允许关闭；原节点消失或真实权限/归属失效须失败保留，不能写当前B或重插。见[任务64](../plan/tasks/app-mac-recording-autosave64.md)与[逻辑分析](../plan/analysis/mac-recording-autosave64.md)。源码/受控验证不能替代真实麦克风与完整像素验收。

## 授权诊断63（内部验证，不增加产品界面）

研究61表明旧Start失败只能定位在AV授权预检，尚不能区分系统completion未到、主队列未处理或桥接交付未结算。新增默认关闭的进程环境诊断，固定事件和有界预算，仅输出无内容request ID、单调时间、stage/code、公开status/Boolean等标量；组件不自行落文件、不联网、不含音频、笔记或裸指针。受控测试可保存合成事件作为验证证据。Rust与ObjC共用request ID，分别记录OS completion进入（主线程派发之前）和main处理，以便后续正常验收判读。关闭开关不输出诊断，不改变授权、截止或生命周期。

```text
明确Start → Rust dispatch → native/main/window → AV status → request-issued
                                                     │
                         OS completion-entry（任意线程）
                                      ↓ dispatch main
                         main completion → pending clear
                                      ↓
                         Rust receive → window revalidate → JS settle
```

30秒native截止、两段35秒Rust等候及Session45秒截止保持。timeout/close只交付旧结果，不清仍在系统等待的pending或释放callback context；迟到completion只清原pending、不复活Session。JS错误保留code及可选stage/request ID，UI沿用既有message；busy/timeout仍各自独立，不推断为denied。诊断源码/伪OS检查不代表真实麦克风请求成功，当前包和手机现场保持。具体范围见[任务63](../plan/tasks/app-mac-recording-diagnostics63.md)。

诊断不能反向阻塞授权：main、OS completion及FFI仅非阻塞地尝试放入固定有界队列，由独立诊断writer处理输出；饱和有明确丢弃/截断标记。不得在producer同步写stderr、等待输出锁或join writer。writer卡住、stderr不读取也不能阻止completion进入主队列、超时交付或context释放。此诊断线程不改变原授权操作的main线程约束。

桌面录音窗口不默认alwaysOnTop，不阻止主窗点击/键盘/编辑，不依赖主窗当前选中哪篇笔记。blur、普通visibility hidden、最小化、切换应用/笔记均不主动暂停或销毁真实采集。录音窗口关闭时仍沿“真实收尾→原笔记ACK→关闭”而非隐藏丢弃。主窗在其拥有的录音活跃时普通关闭可隐藏保活原编辑器/保存队列，录音窗口继续；普通主窗重显保持同一owner。整应用明确退出必须先完成所有录音及原正文保存，失败保留窗口/录音并终止退出；强杀/崩溃不承诺恢复内存音频。此处关闭规则覆盖早期“不扩张整体退出”的旧工程范围。

明确退出应用的等待期是短暂保存屏障：每个参与正文窗口在首次异步等待前封住新编辑/创建/格式等正文变更入口，再完成录音与最新队列并确认退出，不能先ACK随后接受未确认的新正文。这不适用于普通后台录音或普通主窗隐藏。退出取消、失败或超时后恢复仍有合法权限的编辑入口，不能绕过真实撤权，也不能抛弃活动组字/未保存内容；新窗口加入或旧窗口销毁同样不得跳过退出参与者约束。

原笔记A的临时卡与游标映射仅投影会话；用户可继续编辑A、切B工作。源EditorA作为同owner稳定挂载，真实本地事务映射插入bookmark，最终在A最新正文中插入一次并经原SaveQueue/Rust ACK。其他B正文/选区/焦点不被强行切回。不能简单删除旧目标版本检查或直接写旧快照；录音专用校验须证明原note/owner/授权/窗口incarnation一致、最新可信A正文与待存队列一致。外部更改/真正撤权/锁定/删除/源editor销毁导致无法安全映射时，子窗保留同File显示失败，绝不写到当前B或覆盖A。

窗口间仅定向、带不可猜测session与operation的控制/状态/提交协议；捕获和File由录音窗持有，后端附件operation始终归原owner窗，原owner确认实际A正文ACK后才向子窗回成功。重试必须复用原owner缓存的同一File/operation，不重复解码为新File或重复插入；回执丢失/重复请求可查询同提交结果。事件到达、stop或store完成不等于正文ACK。若owner非正常失去存活，录音窗明确错误并保留File，不暗中冒认新窗口身份。

文件接收与正文ACK分开：子窗只有收到真实owner的文件已缓存确认后才能停止携带文件内容；首次relay失败或接收不确定时可重送相同缓存字节，owner按同session/operation幂等接收且只构造一次File。不能在发送之前自设“已传输”而让重试永远缺少文件。非正常子窗Destroyed后若原owner随后给出真实正文ACK或明确安全无音频终态，registry可清除已不存在的child记录；失败、未知或冒认owner不能借此解除退出保护。

新窗口label精确为`recording-<标准小写UUID>`，URL为应用本地recording专用入口；新窄capability只授必要窗口/事件和麦克风预检，不能泛用note-*伪装。初始建议宽320、最低280 CSS px，高600、可调整大小；这是工程起点，内部视觉继续以原图比例校准。

┌────主窗：A/B可编辑────┐ ┌─录音─⋯×┐    ┌文件夹┬列表┬正文A/B┬新录音 ⋯×┐

采集所有权不随呈现迁移：唯一录音child从创建到最终ACK始终挂载同一桌面控制器、Session、MediaStream与活动时钟；当前窗展开只渲染同一状态的共享视图并定向发送真实控制。不能因切换呈现在owner重新getUserMedia、重建MediaRecorder、复制Audio/blob URL或将计时推测为实际播放。64的暂停会终结分段，继续时在原stream建立新分段，各累计版本有自己的不可变File与operation；模式切换不触发这些动作。原owner持A保存队列，保持50校验、保存失败重试、关闭/退出与52真实窗口权限规则。手机保持现有sheet，不加入桌面双模式。

状态投影须含本会话真实phase、首次开始时间、累计活动时间、实际播放位置/可定位范围、播放/准备/错误、真实历史波形采样与动作可用性。事件带同session/operation/owner/child及递增序号，拒绝旧会话/旧状态；波形复用有界聚合并节流，不传音频副本或伪造波形。实际开始、暂停、继续、试听/暂停、±15、绝对seek、预览重试、完成/关闭都由原child控制器执行；主窗仅显示child已确认的实际结果。seek及样本值须有限、范围合法、数量有界，未知消息失败可见。

模式切换须有确认顺序：先让目标视图就绪且收到最新同会话状态，再隐藏原呈现；浮窗切入主窗时显示/恢复原owner，主窗切回浮窗时先show成功再撤展开视图。不能出现两边都隐藏，不能把隐藏当关闭/销毁或丢弃；失败保留原可操作视图并给出错误。切换期间不暂停Session/试听、不清计时或波形、不调用附件提交。重复点击/迟到响应不得回滚最新模式。主窗最小化/失焦不暂停；主窗普通关闭若正在展开，先确认浮窗可见，再隐藏原owner并保持原编辑器；若无法显示浮窗则取消此次主窗关闭。子窗意外失去存活、ACK、显式Quit等仍沿50规则，不以切模式绕过安全保存。

两种视图的“×”都调用现有安全结束/未开始取消流程，不是静默丢弃。两者的录音状态、禁用状态、预览位置和错误一致；切换不抢其他笔记为原A。真实新包必须在录音中及暂停试听中反复切换，确认同一录音最后只在A显示一张累计录音卡，A/B最新文字与焦点保持；64内部保留多份不可变版本，不要求只有一个物理附件。DOM夹具只能作为受控状态/控制与布局证明；隐藏child背景设备采集、远程播放的WebKit用户手势限制及实际像素都要实包验收，不能以模拟事件放行。

试听计时由实际媒体事件确认；暂停播放仍保留最近实际位置，不能跳回活动录制总时间。真实未就绪时保留活动时间并给出状态。±15和绝对seek复用同一媒体可定位范围与seeked确认；拖动不会把UI预测值当成实际到达。鼠标/触摸拖动及键盘左右、Home/End对应真实seek，忙碌和失败不伪装成功。首次回放或播放结束后再次播放从头；当前播放的结束事实来自media ended。
