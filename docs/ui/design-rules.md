## 整体布局

```text
桌面：主工具栏 → 目录 / 列表 / 正文（各栏有独立最小尺寸）
设置：分类侧栏 │ 外观、字号、界面细节与即时示例

手机：标题 + 操作同一行 → 搜索/列表，或正文 + 底部编辑工具栏
设置：首页分组 → 外观与字号 → 界面细节（整页可滚动）
```

桌面延续现有浅灰栏、白正文、黄色选择状态和 920×660 设置面板。手机保留可触控的单栏/底栏，不通过整体 transform/zoom 缩小桌面界面。设置页保留既有外观卡片、界面和编辑器各五档字号，新增可折叠“界面细节”；默认折叠，避免增加常规设置负担。展开后按图标、操作区域、菜单间距、圆角顺序，含实时示例与“恢复界面细节默认值”。移动版放在同分类的滚动页中。

## 变量与边界

所有尺寸以 CSS 逻辑 px 表述，图标尺寸和可点击区域分开。字号继续使用 tiny/small/medium/large/huge；不以减小命中区域强迫文字适应。

| 规则 | 桌面默认/范围 | 手机默认/范围 | 应用范围 |
| --- | --- | --- | --- |
| 图标 | 默认沿现有视觉比例，细节倍率 80%–120% | 同倍率，有界尺寸 | Web 工具栏、菜单、侧栏、设置、附件操作；原生工具栏同步可支持的图标比例 |
| 按钮命中区 | 默认现有密度；最短边至少 28px，细节倍率 100%–130% | 最短边至少 44px，倍率 100%–120% | 图标/文字按钮、底部工具栏、关闭/返回；窄屏优先折行/溢出菜单 |
| 菜单间距 | 紧凑/标准/宽松：行内额外纵向间距 0/2/4px | 同选项，行高始终至少 44px | MenuSurface、子菜单、点击展开和右键入口 |
| 圆角 | 标准默认；倍率 0%–150%，最终值 0–24px | 同范围 | 按钮、菜单、卡片和 Web 浮窗；圆形录制/播放按钮保持语义形状 |
| 字号 | 界面、编辑器各五档，沿现有数值 | 同五档，布局独立 | 界面文字/正文分别映射，不合并设置 |

使用有界枚举/数字结构保存 `interfaceDetails`，带明确版本；不接受任意 CSS 字符串、未知版本/键、非有限数、超限值。缺少该字段代表旧设置，使用显式默认；重置只重置这些细节，保留字号、主题和其他业务偏好。持久设置更新与 archive 导入都验证完整对象；错误保留旧设置并显示可恢复原因。更新失败不得显示已保存成功。预览和真实产品控件使用同一变量映射，不能只改变示例。

配置结构采用 `version: 1`、`iconScale`（80–120整数百分比）、`desktopHitScale`（100–130）、`mobileHitScale`（100–120）、`menuSpacing`（compact/standard/comfortable）、`radiusScale`（0–150）。默认分别为100、100、100、standard、100。点击区域分开保存，设置页只呈现当前平台对应的一项；桌面配置同步到手机时不能把超范围数值静默截断。其余共享规则沿用同一值，实际像素由对应平台布局计算。恢复默认重置完整细节对象，不改变主题和两个字号。

基础变量放唯一入口：界面/编辑器字号、几何密度、图标、命中区、菜单 gap/padding、按钮/卡片/菜单/面板圆角。现有 `--ui-scale` 仅作为兼容映射，逐步减少重复数值覆盖；不用全局 `svg` 选择器修改正文插图或速绘笔画。按钮反馈沿用统一 hover/active/focus-visible/disabled。

## 2026-11-20 布局与系统表面补充

- **内容预算优先。** 桌面三栏以正文最小宽度 `320px`、目录 `220px`、列表 `280px` 计算；三栏不足 `820px` 时降为两栏，两栏内容不足 `600px` 时降为专注。不得先把固定栏宽塞进窗口再压缩正文或命中区。用户偏好栏宽只在有效范围内 clamp，压缩窗口不写回偏好。
- **一个区域一个常驻主动作。** 集合页头、编辑器工具栏和底部 footer 不能同时暴露同一个创建动作。桌面列表/画廊、专注、独立窗口和手机 FAB 分别声明动作可见性，切换布局后保留同一处理器、快捷键和焦点顺序。
- **手机页头只保留必要层级。** 根目录一个文件夹入口，目录页一个返回入口，标题占中间可伸缩列，右侧一个显示选项入口；设置、视图切换和低频动作不回到页头平级竞争。所有显式操作至少 44px 命中区，长标题可换行或独占一行。
- **焦点与状态使用语义 token。** `button`、`input`、`select`、`textarea`、`summary`、菜单触发器和设置搜索统一使用 `--focus`；普通文字目标 ≥4.5:1，必要非文本状态目标 ≥3:1。选中、悬停、按压、禁用和忙碌必须分别有可辨认状态，不能只靠颜色表达选中。
- **空态必须给出下一步。** 首次空目录、搜索无结果、筛选无结果、标签筛选无结果、读取失败和保存失败分别呈现对象、原因和可执行动作；查询无结果使用“清除搜索”，筛选/标签无结果使用“清除筛选”，手机与桌面遵循同一语义。搜索无结果保留查询与范围，清除动作不丢失当前页面焦点；仅标签筛选或“查询 + 筛选”不得误报文件夹为空，清除动作必须移除对应筛选范围。
- **系统栏是相邻表面的延伸。** Android 顶部状态栏取页头/页面表面，底部导航区取操作栏/集合表面或已打开的格式面板；设置页顶部取页头纸面、底部取分组内容表面，不能把整页写成同一个颜色。这里的“颜色一致”指上下各自与相邻内容表面连续，不要求两个方向强制使用同一个 RGB；同一页面上下相邻表面相同（如集合页）时必须使用同一表面色、不得产生色差，编辑页和设置页则允许因页头与操作栏/内容表面不同而分别取色。启动页在 React 之前按自身纸面投影，`.app` 挂载后停止覆盖页面投影；原生首帧使用日/夜回退色。颜色来自当前主题和实际可见表面，图标明暗按各自背景亮度决定。Android 10+ 使用 edge-to-edge 条带，Android 8–9 使用平台系统栏底色以避开浅色系统栏遮罩；两条分支共享同一份前端投影，且系统栏绘制与 WebView 容器共用同一份 systemBars/IME inset，不新增第二套 safe-area padding。
- **组件收敛顺序。** 先合并重复的移动布局规则，再收敛图标按钮、菜单触发器、设置行、分段、卡片和状态提示；平台 CSS 只决定几何，不重新定义主题色。Android 宽屏、macOS 原生工具栏和浏览器窄窗都纳入同一组件的验收矩阵。

## 2026-11-20 高频组件基线（源码已实现）

- **工具栏先分组再溢出。** 桌面编辑工具栏按“编辑 / 插入 / 分享 / 更多”排列，组间使用固定间距与低对比度分隔线；宽度不足时按同一顺序进入溢出菜单，菜单内保留组间分隔。分组不改变处理器、快捷键、权限或 `aria-label`。
- **卡片先定结构再定内容。** 手机集合卡片同排等高；标题两行、摘要三行、日期贴底，更多入口固定在右上并保留 44px 命中区。列表/单列/双列复用同一 DOM，不复制标题、日期或动作。
- **设置控件只认角色。** 分组、行、选择器、分段器和搜索框分别消费 `--settings-radius-group`、`--settings-radius-control`、`--settings-row-min`；移动端整组控件换行，但命中区不缩小。错误块使用同一危险表面、左侧语义边和正文/次要文字层级。
- **菜单与按钮共享界面细节。** 菜单面板、菜单行、桌面工具、格式按钮、标签按钮和卡片更多入口分别消费按钮/菜单圆角 token；圆形创建、播放和录制保持语义圆形，不参与方角收敛。
- **焦点不是选中。** 菜单首项可以被程序化聚焦，但不得默认用强调色铺满整行。指针打开不使用强调色填充；键盘焦点使用共享 `--hover` 表面和 2px 内嵌 `--focus` 环；危险动作使用危险表面与危险文字。`aria-checked` / 已选样式才使用强调或选中表面。
- **面板控件表面跨明暗同构。** 当面板底使用 `--sidebar` 时，内部控件不要直接复用 `--grouped`；使用由 `--ink` 与面板表面派生的控件表面，使浅色下控件略深、深色下控件略浅，避免同一组件在两种明暗中呈现相反的层级。
- **焦点环只有一套尺寸。** 数据管理、同步、智能文件夹普通控件、设置、更新和 MCP 测试器统一使用 2px `--focus`；移动主创建按钮可以使用高对比度专用外环，但不得把普通控件退回低对比度强调色。macOS 普通新建文件夹名称框的 3.5px 连续暖环是既有 Mac26/29 测量得到的原生表单例外，不得扩散到普通控件，也不在没有新设备证据时擅自改成 2px。

本节描述当前源码行为；浏览器 fixture 通过不等于 Android/macOS 实体设备、IME、系统菜单或辅助技术验收。

## 层级与系统能力

共享语义层级依次为：正文内容 → 编辑器控件 → 固定工具栏 → 非模态浮窗 → 普通菜单/子菜单 → 设置等模态表面及其菜单 → 访问/锁定屏障 → 首次启动/致命恢复。具体 z-index 只在变量入口定义；局部 stacking context、portal 目标和原生窗口顺序都纳入审查。访问屏障可盖住所有敏感正文/媒体和普通浮窗，任何个性化不能降低该保证。

不把原始 z-index 暴露为用户设置。系统 AppKit 菜单的字体、间距、圆角由 macOS 管理；设置明确标注“菜单间距与圆角作用于应用内菜单，系统菜单遵循系统样式”。原生 toolbar 可以同步的尺寸通过其现有投影契约更新，系统最小尺寸/窗口布局不能由 Web 设置绕过。非模态原生预览的窗口层级仍由访问/关闭控制器管理。

## DESIGN100 源码实现与所有权

`interfaceDetailVariables` 是细节映射唯一入口，App 的 `recording-layout`（含录音停靠区）与 `.app`、设置示例共享其输出。`design-controls.css` 在页面布局后加载，统一实际按钮/输入/菜单命中区、明确 UI 图标容器和圆角；不匹配正文插图、速绘 SVG 或波形内容。圆形播放、录制和色板保留圆形。表格在正文内预留操作 gutter，标记的容器与子按钮均满足平台命中下界，选择框仍跟随真实单元格；不修改表格文档、选择和历史规则。

桌面工具栏按可用宽度与独立图标/命中倍率计算溢出；设置在窄短窗内滚动。手机不使用桌面几何缩放，320px 时字号选项可折行，返回按钮保持单行。长菜单可滚动，子菜单按视口及原生顶部保留区定位，并在自身/触发器尺寸变化后重算。

`design-tokens.css` 是层级数值唯一入口，首次启动 HTML 与产品入口均加载。语义顺序为 content(0)/content-overlay(1)、editor(10)、toolbar(20)、preview(30)、menu(40)/submenu(41)、modal(50)/modal-menu(60)、notice(70)、access(80)、startup(100)；背景 decoration(-1)。MenuSurface 标注模态来源，portal 继承 App 变量；访问覆盖同时隐藏普通菜单和录音停靠区。浮窗/模态不依靠各自不断增加数字争抢前景。

`ConfirmedSettings` 持有已确认的设置；App 更新先串行持久写入，再读取权威设置后发布到真实控件。失败不会发布待保存值；失败时重发当前快照还原临时栏宽拖动。workspace 读取票据和世代防止晚到旧读取覆盖新 ACK/外部更新，确认读取期间发生外部采纳则重新读取。外部 refresh 和重载仍能采纳实际数据库设置。设置页原有 100A 局部 ACK 与严格校验保留。

原生投影携带 `iconScale`(0.8–1.2) 和 `hitScale`(1–1.3)，缺省各为1；Rust 验证非有限值和边界。AppKit 控制器独立改变 symbol point size 与按钮 frame，hit-only 更新保留现有 symbol 对象，note/revision 更新也不强制重建按钮。toolbar 高度与保留区随实际几何一致计算。系统 NSMenu 字号/圆角依然由系统管理。

本阶段验证为源码、真实 Chrome App + 隔离生产 Store/SQLite、真实隐藏 NSWindow/AppKit 控制器；不是双端最终安装包/ADB/实体触摸板结论，后者由 FINAL101 单独验证。
