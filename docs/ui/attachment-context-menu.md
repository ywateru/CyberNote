# 附件右键菜单（APP93）

依据用户2026-11-07新要求，笔记内所有用户附件增加统一右键菜单。图二未显示可用菜单内容，不能据此宣称精确还原原版菜单；沿用现有应用圆角、浅/深色材质、图标、分隔线和高亮。

## 结构与区域

```
笔记正文
  [图片 / 音频卡 / 视频 / 普通文件卡] ← 右键、菜单键
                ┌─────────────────────┐
                │ 预览 / 播放或暂停    │ ← 仅类型实际支持时
                │ 保存附件…           │ ← 原字节另存
                │ 显示信息            │
                ├─────────────────────┤
                │ 从备忘录中移除      │ ← 当前正文事务，可撤销
                └─────────────────────┘
```

原始导入内部记录不属于用户附件，不出现卡片、附件浏览列表或菜单。用户自行添加的同名JSON仍是普通用户文件，不按名字隐藏。内部记录可在数据管理中以内部数据项如实计入物理占用，不显示成普通附件。

## 交互

- 菜单在实际右键点显示，并在视口四边留至少8px；菜单键/Shift+F10以聚焦附件边界为锚。菜单可键盘上下移动/Enter触发、Esc/外部点击关闭，关闭后合理恢复焦点；开菜单不更改正文/插入光标或意外播放。
- 图片复用现有预览；已保存音频/视频复用实际媒体控件；无可用预览/播放能力的文件不显示假“打开”。保存统一走 `saveAttachmentOriginal`，使用真实原字节导出和当前owner授权；取消不显示成功。
- 信息显示实际文件名、类型/MIME、大小以及确有的录音时间，不虚构不存在的日期/尺寸。信息属于轻量独立面板，不阻塞其他笔记操作；关闭可返回当前文档。
- 移除只删当前笔记对应附件节点，经过现有Editor保存路径并支持Undo/Redo；不直接删除底层原文件破坏撤销/其他owner。导出失败显示错误，可重试。删除实际磁盘文件沿用既有生命周期。
- 请求绑定noteId、attachmentId、Editor/访问代际，切换笔记、同步覆盖、锁定、窗口退出、文档引用消失或权限失效时关闭/拒绝迟到动作；不能作用到当前新笔记。同一附件导出防重复。录制中临时卡不能作为已保存附件导出或移除。

## 状态与响应式

保存中/源媒体读取失败时按真实能力禁用相应菜单项，提供错误；保存、删除的可写权限分别检查，不能单靠菜单打开时的检查。菜单层级在编辑器上方、系统原生对话框下方；不能全屏闪烁或覆盖原生toolbar命中区域。共享前端不破坏手机触控/原有播放、拖动、图片预览；本轮不操作原Android设备。

## 组件与入口

复用 `Editor.MediaView` 的全部attachment节点、`ImagePreview`、`attachment-export`、已有菜单样式及debug系统。只发布真实接线的能力，不添加没有实现的复制/共享/重命名菜单项。
