# CyberNote UI 质量审查与改进路线

2026-11-21 · 源码基线：`f8ed9027` 加本轮工作树 · 目标发布：`0.2.0004`

本页审查桌面、手机、原生登录窗口和 Android 系统表面。目标不是把不同平台做成同一套外观，而是让内容预算、层级、动作、焦点、空态、错误和平台表面遵循同一套产品规则。文中明确区分：

- **本轮已实现**：代码已修改，并有对应静态检查、浏览器 fixture 或真机证据。
- **改进建议**：尚未实现的产品/设计建议，不应当作为当前发布通过证据。
- **待验收**：需要准确构建、发布签名包或真实设备完成的项目。

相关契约：[双端呈现](adaptive-presentation.md) · [设计规则](design-rules.md) · [设置规格](preferences.md) · [账户界面](account-sync.md) · [主题与呈现架构](../architecture/theme-presentation.md) · [上一轮 UI 审查](ui-quality-audit-20261120.md)

## 审查结论

当前产品已有稳定的三栏工作区、单栏移动流程、五档字号、八套主题、共享设置控件和可复用的账户/附件组件，基础不需要推倒重建。距离全球顶级产品的主要差距集中在六类：

1. **内容与媒体的层级要清楚。** 画廊缩略图不能覆盖正文，也不能让同一张图片在一个卡片里出现两次。
2. **原生窗口只做平台该做的事。** 登录窗口不应再叠加一排网页风格按钮；关闭窗口就是取消，授权状态由账户页承载。
3. **产品能力应收敛为一个默认路径。** 凭据只使用本地加密文件，不把实现细节变成用户需要理解的设置项。
4. **系统栏必须是页面表面的延伸。** Android 顶部状态栏和底部导航/手势区分别跟随相邻表面；同一页面上下相邻表面相同时，RGB 必须一致。
5. **设计语言需要一个可审计的来源。** 字号、间距、圆角、阴影、焦点和动作层级不能继续由多个页面级 CSS 片段各自定义。
6. **状态、可访问性和平台连续性要像主流程一样验收。** 空态、错误、键盘、IME、减少动态效果、横屏和发布签名包都需要明确门槛。

## 画廊：媒体是信息，不是覆盖层

### 问题

旧画廊预览把缩略图绝对定位在卡片右上角。它既没有参与文字布局，也没有给正文留出稳定空间，结果是小卡片中标题、摘要和图片互相挤压；同一张缩略图还可能在同一卡片里出现两次。这种“把图片盖在内容上”的实现不符合内容型产品的可读性要求。

### 已实现规则

```text
┌──────────────────────────────┐
│ 标题（最多两行）      ┌──────┐ │
│ 摘要（可换行、裁切）  │ 媒体 │ │
│ 表格/绘图提示         └──────┘ │
└──────────────────────────────┘
```

- 有媒体时使用两列网格：文字列 `minmax(0, 1fr)`，媒体列桌面 58px、窄屏 44px。
- 媒体容器使用 `aspect-ratio: 1`、`overflow: hidden` 和主题分组表面；缩略图本身为 `position: static`，不再覆盖文字。
- 无媒体时保持原预览布局，不凭空保留媒体空列。
- 选中态和键盘焦点只描边预览卡；悬停使用轻微背景、边框和阴影变化，不使用夸张位移或高饱和覆盖。
- 尊重 `prefers-reduced-motion`，关闭过渡。

### 验收

- 320/390/430px 与桌面 700/820/1000/1100/1280px：媒体与文字边界不相交，媒体在卡片内，卡片无横向溢出。
- 长标题、空正文、只有媒体、表格、绘图、搜索高亮和选中态：标题/摘要不被媒体截断，焦点环不被卡片裁切。
- 真实 macOS WKWebView：缩略图清晰、无双重渲染、无鼠标悬停闪烁。

## 原生登录：窗口关闭就是取消

### 已实现规则

- **macOS**：登录窗口只保留系统标题栏的关闭按钮；WebView 从内容区顶部开始，最小尺寸 `420×560`，不提供“在浏览器中继续”或“取消登录”原生按钮。
- **Android**：登录对话框只保留标题和 WebView；不创建原生按钮行；系统 Back、关闭对话框和窗口 dismiss 都走同一次取消清理。
- **账户页**：授权中显示当前实际 surface、等待说明和唯一的“取消登录”；关闭内置窗口等同取消，迟到回跳不能恢复下一次事务。
- **兼容边界**：内部 `openLoginInBrowser` 命令仍保留给既有调用方，但产品界面不再显示“在浏览器中继续”。用户可以在登录前通过“登录方式”选择系统浏览器。

### Logto 托管页

本轮只通过 Management API 修改全局 sign-in experience 的 `languageInfo`、`color` 和 `customCss`，没有覆盖无关设置：

- 默认语言 `zh-CN`，保留自动识别。
- 主色 `#19191c`；深色主色 `#f2f2f4`；中性画布、白色/深色卡片、细边框、柔和阴影。
- 输入框和主按钮 48px；Logo 44px；移动端卡片按可用宽度收缩。
- 真实 PKCE 页面已用无头 Chrome 验证：桌面浅色/深色卡片 `420×446`，移动 `366×482`；输入框/按钮 48px；Logo 自然宽度 `150`；不再显示“app logo”占位符；无横向溢出和页面错误。

后续建议：如果同一 Logto 租户还承载其他产品，应将品牌配置迁移到应用级 sign-in experience 或独立租户，避免全局 CSS 影响其他应用。

## 凭据存储：只保留本地加密文件

### 当前产品契约

- 设置页不再显示“凭据存储”，也不提供“系统钥匙串”或“改用本机加密文件”的切换。
- macOS 使用 `EncryptedFileStore`：AES-GCM 密文、本机 `0600` 密钥文件、原子替换、进程独占、完整性校验和损坏拒绝。
- Android 使用 Keystore 保护的本地加密文件。Keystore 是 Android 内部保护机制，不是用户可选择的“系统密钥存储”设置。
- 账户状态 DTO 不再包含 `credentialStorage`；IPC 不再接受 `setCredentialStorage`；`platform-keyring` feature 和 `KeyringStore` 再导出已移除。
- 旧 Keychain 项**不读取、不删除**。发现旧版 Keychain 偏好或安装标记时，先把当前绑定归档到私有会话记录，再清除活动绑定，要求重新登录；本机笔记和附件不受影响。
- 重新登录会重新验证账户；匹配同一同步空间时可复用有效设备身份。同步仍需用户明确重新开启。

### 为什么不保留设置

对普通用户来说，“系统钥匙串”和“本机加密文件”不是可理解的产品选择，而是实现细节。保留它会产生三套不必要的复杂度：

1. 用户需要理解系统授权提示、重建签名、迁移失败和回退路径。
2. 产品需要维护两套安装身份、两套恢复语义和两套状态字段。
3. UI 必须为一个低频实现分支增加确认、错误和禁用状态，挤占账户主流程。

只保留本地加密文件后，账户页的主任务是登录、设备、同步和退出；凭据保护由原生层负责，不再要求用户做技术选型。

### 验收

- 新安装登录、重启恢复、退出、换账户和同步开启/暂停。
- 旧 Keychain 安装升级：旧项不被读取或删除，绑定归档，重新登录后可复用设备身份，笔记/附件完整。
- 加密文件缺失、损坏、权限错误、重复 owner 和原子替换中断：明确失败，不生成替代身份。
- Android 强停/重启后的 Keystore 保护记录恢复；不以桌面行为代替 Android 证据。

## Android 顶部状态栏与底部操作区

### 产品规则

1. **系统栏是相邻表面的延伸，不是独立装饰。** 顶部状态栏延续其下方页头或页面表面；底部导航/手势区延续其上方操作栏、集合背景或格式面板。
2. **上下分别取色，但各自必须连续。** 同一页面上下相邻表面相同（如集合页）时，顶部和底部必须使用同一 RGB；设置页、编辑页等上下相邻表面不同，允许顶部和底部使用不同颜色。
3. **颜色来自实际可见表面。** 先读取当前页面元素 computed background，失败时回退到语义 token；不读取正文、图片或用户指定文字颜色。
4. **图标明暗由表面亮度决定。** 浅色表面用深色系统图标，深色表面用浅色图标；不能只根据 `schemePreference` 猜测。
5. **inset 只有一个所有者。** `MainActivity` 负责 systemBars/IME 的 WebView 容器避让；系统栏绘制使用同一份 bars inset，不新增第二套 safe-area padding。
6. **页面切换重新投影。** 启动页、集合、目录、编辑、设置、格式面板、明暗/主题、窗口尺寸和 IME 变化都触发有界重算，不保留旧页面颜色。

### 页面映射

| 场景 | 顶部相邻表面 | 底部相邻表面 | 语义回退 |
| --- | --- | --- | --- |
| 笔记集合 | `.notes-pane` / 集合页头 | `.notes-pane` / 集合背景 | `--grouped` |
| 文件夹目录 | `.sidebar` / 目录表面 | `.folder-footer` | `--sidebar` / `--grouped` |
| 编辑页 | `.editor-header` | `.editor-tools`；格式面板打开时为 `.mobile-format-panel` | `--paper` |
| 设置弹层 | `.preferences` / 设置页头 | `.preferences-body` / 设置内容表面 | `--paper` / `--grouped` |
| 启动页 | `.startup` 纸面 | `.startup` 纸面 | 日/夜纸面色 |

### 当前真机证据

设备：Samsung `SM-G9500`，Android 9（API 28），1080×2220，系统手势导航；当前 QA 包 `com.local.notesclone.cyberbusqa`，`versionName=0.2.2`，调试 APK，Ocean 主题、深色外观。

像素采样确认：

| 场景 | 顶部 | 底部 | 结论 |
| --- | --- | --- | --- |
| 集合页 | `rgb(223, 237, 245)` | `rgb(223, 237, 245)` | 上下与集合表面连续 |
| 编辑页 | `rgb(237, 248, 253)` | `rgb(237, 248, 253)` | 上下与编辑表面连续 |
| 设置页 | `rgb(237, 248, 253)` | `rgb(223, 237, 245)` | 顶部纸面、底部分组表面分别连续 |
| 深色设置 | `rgb(16, 38, 49)` | `rgb(11, 28, 38)` | 顶部/底部各自连续，图标为浅色 |

这组证据只覆盖该设备、手势导航、当前主题和调试包；不能代替发布签名包、三键导航、IME、横屏或冷启动验收。

## P1 · 设计语言与交互统一建议

| 方向 | 当前差距 | 改进建议 |
| --- | --- | --- |
| Design token 单一来源 | 组件 CSS 仍有大量局部字号、间距、圆角、阴影和页面级色值补丁；同一语义可能在不同页面使用不同常量。 | 建立 `surface / text / border / action / state / focus / spacing / radius / elevation / motion` 分层 token；主题只改语义值，组件只消费语义值。禁止在页面选择器中新增十六进制色值，除非是主题注册表。 |
| 字体与排版 | 系统字体方向正确，但角色字号、行高和中文行长没有统一验收表；不同页面存在 0.72–1.15em 的局部缩放。 | 定义标题/副标题/正文/元信息/按钮/标签六类角色；中文正文行长建议 30–45 个汉字，行高 1.6–1.75；五档字号下检查断行、截断和数字对齐。 |
| 间距与形状 | 4/8 网格已部分使用，但仍存在 43、54、55、58px 等组件局部值；圆角来源分散。 | 以 4/8/12/16/24/32px 为主尺度；圆角按按钮、输入、菜单、卡片、模态分别定义；圆形只用于创建、播放、录制等明确语义。用截图和 DOM 几何验证，不靠肉眼记忆。 |
| 动作层级 | 同一区域可能出现多个同等级主按钮；退出、重新登录和危险操作与普通动作视觉接近。 | 每个区域最多一个常驻主操作；危险动作使用独立语义色和确认；次级动作使用文字按钮或菜单，不靠颜色堆叠制造层级。 |
| 状态完整性 | 默认/悬停/按压/聚焦/选中/禁用/忙碌并非所有组件都有同一套规则；部分图标按钮的命中区与视觉尺寸混在一起。 | 建立共享状态矩阵；键盘焦点统一 2px `--focus` 环；手机命中区 ≥44px、桌面 ≥28px；悬停只改变表面/边框/阴影，不改变布局。 |
| 对比度与可访问性 | 主题已有对比度基线，但新增组件仍可能绕过检查。 | 普通文字 ≥4.5:1，必要非文本状态 ≥3:1；焦点、选中、错误不能只靠颜色；所有图标按钮有可读名称；尊重减少动态效果和高对比度模式。 |
| 响应式预算 | 已有 resolver 和 320px 移动规则，但极端长标题、空正文、附件、搜索无结果和横屏组合仍缺少系统采样。 | 先算内容预算再决定导航/列数；不通过整体缩放、压缩命中区或隐藏业务动作换宽度；把 320/390/430px、短窗、横屏和 IME 纳入固定回归。 |
| 原生与 Web 连续性 | macOS/Android 登录窗口、系统菜单、键盘和窗口 chrome 仍是独立实现。 | 原生只承载平台能力；品牌、文案、加载、错误、焦点和关闭语义与 Web 账户页共享同一契约；不复制第二套表单或第二套状态机。 |

## P2 · 体验细节与工程化建议

| 方向 | 建议 |
| --- | --- |
| 启动与首屏 | 冷启动前使用已确认主题的纸面色和系统栏回退，React 接管后校正；避免白闪、粉白系统栏和字体跳变。加载超过 300ms 才显示骨架/进度，避免闪烁。 |
