## Build driver finding: explicit entitlement required

The old driver (`docs/verification/sync91/mac-build/build-driver.py`) derives the delivered app with `codesign --force --sign - --timestamp=none APP`. It neither supplies entitlements nor preserves them. The installed codesign manual states that without preserve-metadata the old signature has no effect on signing, and --entitlements embeds the supplied data. Reusing that command unchanged can strip APP92's newly required `com.apple.security.automation.apple-events=true`; strict signature verification alone does not establish this entitlement. This is a required APP92 build-driver repair assigned to the original developer, not a reviewer product change. Use explicit frozen source Entitlements.plist on derived signing, then independently display and parse actual original/derived entitlement plists. Do not assume preserve-metadata works on linker-signed binaries: the same manual documents that exception.

Current source config correctly selects Info.plist and Entitlements.plist. The purpose text describes reading system Notes and copying selected notes/attachments without modifying originals. It expresses requested use, not a promise of complete native-object export or prior automation authorization. Final audit must check the actual bundled Info.plist retains exact source purpose values, including Apple Events, microphone and camera, plus bundle identifier/name/executable/minimum OS. The extracted entitlement dictionary must equal the intended source dictionary (no unexpected sandbox/debug additions); verify derived app and archive represent the same bytes. This does not prove TCC consent or successful Apple Events from a signed packaged launch.
