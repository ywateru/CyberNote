## 所有权

会话只管理交互状态、可见面板、焦点与输入法意图、当前选区书签和导航失效。文档内容、历史、Rust 保存/授权、录音采集与附件归属仍由各既有控制器管理。不得通过一个“mode”字符串抹掉桌面录音栏可以和编辑/菜单同时存在的事实。

```text
当前笔记 / 可写授权 / 导航代次
           │
     EditorSession
       ├─正文：浏览 ↔ 编辑（是否请求键盘）
       ├─互斥编辑面板：无 / 格式 / 速绘
       ├─菜单：无 / 当前菜单（可叠在格式/录音上）
       └─录音：独立 owner、生命周期与呈现状态
           │
     平台焦点/输入法适配 → 连接且可写的确切 Editor
```

## 转换契约

| 输入 | 结果与焦点/输入法 |
| --- | --- |
| 进入已有笔记 | 浏览，不擅自弹出输入法；点击正文进入编辑 |
| 新建笔记完成且仍为当前导航目标 | 仅聚焦该 noteId 的已授权、已连接、可写实例；移动端请求键盘 |
| 打开格式 | 捕获并持续映射书签；移动端隐藏键盘；面板保持开启，点击/选中正文不自动关闭 |
| 格式命令 | 对当前有效选区执行，不通过 focus 偷换目标；手动 X/格式按钮关闭后恢复正文与键盘；系统 Back/Escape 关闭规则按平台契约明确区分 |
| 打开速绘 | 取消待聚焦意图、blur 正文、隐藏键盘、冻结原编辑器，捕获确切 owner/授权/原节点；完成/取消不自动恢复键盘 |
| 完成速绘 | 原 owner/授权/原文档仍有效才提交；返回浏览，显式点击正文才开始文字输入 |
| 打开录音 | 捕获录音 owner 与编辑器事务边界；桌面栏可与其他笔记编辑并存；导航不能把录音重归属；手机录音面板按既有行为显示 |
| 展开/关闭菜单 | 菜单目标和书签跟随真实事务；普通菜单叠在手机格式面板上时面板仍保留，不能共用一个可空 menu 字符串意外互相关闭；关闭只退最内层；不得停止录音/丢失正文或隐藏顶部工具栏 |
| 切笔记/目录、返回、同步或访问屏障、目标销毁 | 同步废弃旧焦点/菜单/格式/速绘目标；不得有旧延迟 focus/IME 命令作用于新笔记；保留录音既有保存/取消确认与原 owner |

### 原生 Android 窗口尺寸变化（106，源码已整合、原生待验）

原生Android主窗口使用稳定移动交互身份，不能仅因同一笔记的横屏、分屏或IME引起窗口尺寸变化就切为桌面交互或触发navigation失效。可用宽高继续决定尺寸与滚动；当前同owner、同Editor、授权有效时，格式面板及其选区书签保持。真实导航、撤权、blocked、Editor替换或销毁仍走原失效规则。Mac与普通Web保留原699/700px响应断点；独立笔记窗口保留既有排除规则。本项修正已确定的尺寸/身份边界，不作为原102长按故障的已证原因。

实现入口为 `src/platform/layout.ts` 的稳定平台解析，由初始化和resize共用；手机CSS使用低优先级 `:where(.mobile)`，保持已有细节覆盖顺序。[106独立复审](../plan/reviews/app-android-mobile106-f1-independent.md)接受真实App宽度边界、会话所有权和字号/深色样式证据；该结论不是Samsung真机旋转、输入法或原102长按验收。

## 实施边界

- 用显式事件与状态转换维护不变量，React hook 负责订阅和生命周期；浏览器/Android 键盘桥/原生焦点放入平台适配。
- 面板关闭原因须明确（确认/取消/返回/导航/撤权），集中决定键盘、焦点和是否恢复选区，禁止散落 setEditing/keyboard/blur 拼接。
- 内容编辑门禁继续依赖 SearchEditorGate、accessGate、networkSync、正文保存合并调度器与精确保存队列。会话控制器不得替代授权，不能为恢复 UI 调用 setEditable(true) 绕过门禁。
- 独立录音 owner、附件异步 owner 和浏览搜索停车策略保持既有契约；菜单、面板的可视状态与业务进行状态分开。
- 迁移按创建/普通编辑、格式、速绘、菜单、录音、导航/屏障顺序执行，每阶段检查真实 App 行为，最终从 App 移除重复状态来源。
