## 2. 宿主蓝牙与设备适配器

```text
OS BLE central (macOS / Android)
   -> native Bluetooth broker (permission, connection, profile, lease)
   -> approved device adapter (vendor framing, decode, capabilities)
   -> host router (device, source, sequence, active owner)
       +-- PointCode    -> approved binding -> typed host command
       +-- StrokeBatch  -> drawing session  -> editor transaction
       +-- AudioAsset   -> managed staging  -> attachment submission
       `-- CaptureEvent -> recording owner  -> finalized audio + attachment
```

| 接缝（提案名，非现存 API） | 职责与输入输出 |
| --- | --- |
| `device.adapter` 贡献 | 内置注册表声明版本化 profile、受支持平台、设备匹配、传输与语义能力（`pen.pointCode`、`pen.ink`、`pen.offlineImport`、`audio.import`、`audio.capture`）。匹配信号只用于发现候选；连接后再检查服务和必需特征，用户确认实际设备。仅宣告而未协商成功的能力不可用 |
| 宿主 `device.bluetooth` 服务 | 注册过的适配器可请求 `scan(profile) → candidates`、`connect(candidate) → lease`、`subscribe(lease, channel) → stream`、`read/write(lease, operation, payload)`、`disconnect(lease)`。候选和租约为宿主不透明引用；`channel`/`operation` 由已审查的 profile 映射到白名单 GATT 服务/特征、读写方向及字节上限，不接受插件临时指定任意设备或 UUID。只有适配器看到必要通道的原始报文，第三方 UI 只读经脱敏的设备状态 |
| 宿主 `device.input` 路由 | 将适配器输出校验成有界、带类型事件；验证用户授予的动作、设备/租约、来源及目标上下文后，调用宿主命令或输入控制器。设备协议不接触 `Editor`、`Session`、附件路径、Tauri `invoke`、MCP 或模型工具 |

系统蓝牙许可、CyberNote 的插件授权、指定设备授权及当前捕获意图分开。权限至少拆分 `bluetooth.scan`、`bluetooth.connect`、profile 内的读/通知与受限写，以及笔迹、触发、文件导入、实时录音等领域授权；已连接不等于可收笔迹、触发命令或开启录音。连接按本机绑定标识记录，不能仅用显示名、RSSI、MAC 或一个广播 UUID 当身份凭证；重新配对或 profile 身份变化须重新确认。裸地址、扫描历史、配对/授权和学习的码绑定不随账号或备份迁移。默认日志只记类目、代次和错误码，不记原始报文、码值、笔迹、音频或地址。

由原生宿主管理 macOS 蓝牙用途说明和系统授权、Android 12+ 扫描/连接权限及旧版扫描的定位条件；以后按发行包及真实系统版本核实，Web 预览和不支持的平台返回 `UNAVAILABLE`。M0 只保留能力查询、适配器与输入接口的设计；后续硬件试点先用编译进应用的受信任适配器，不以第三方 UI 沙箱作为硬件授权。固件升级、擦除设备数据及任意配置写入不在范围。

### 生命周期与故障

- 每个实际设备只有一个宿主连接 owner；申请被其他窗口或适配器占用的设备返回 `DEVICE_BUSY`。连接与捕获分开：可保持已连接但未接收输入；默认不后台扫描或捕获。连接失效、撤权、锁定、进入后台（首版）、窗口关闭、插件停用或退出时，终止对应输入/传输，先废弃代次再取消订阅、任务和引用。不对锁定后仍在独立工作的录音硬件承诺已停止，只显示可证实的状态。
- 每个通知绑定连接代次、同源事件序列和接收时间。捕获再绑定输入会话、目标窗口和授权代次；设备时间仅为数据，不能用来授权或当唯一去重键。断线重连产生新代次；可重新连接，但不得继承已布防的触发、半笔画或实时录音。显式恢复离线传输仅在设备稳定文件身份及偏移可核验时允许。
- 扫描、连接、握手、读取与写入有截止时间、取消、队列和载荷上限。连接失败释放部分订阅；通知回调不持有 Session 锁执行 I/O 或等待 ACK。区分 `DEVICE_PERMISSION_DENIED`、`DEVICE_BUSY`、`DEVICE_DISCONNECTED`、`PROTOCOL_UNSUPPORTED`、`STALE_CONTEXT`、`LIMIT_EXCEEDED`；损坏帧、截断和溢出不可冒充成功。宿主重试只重放确认为只读或幂等的操作；不盲重放开始录制等有副作用的命令。

## 3. 点读码触发与实时手写

| 归一化接口 | 最小数据与规则 |
| --- | --- |
| `PointCode` | 连接代次/序列、`live` 或 `offline`、版本化 `codeNamespace`、适配器定义的无损 `codeId`。SmartPen profile 可投影 `SA/SB/SC/SD/index` 供用户核对，绑定键使用完整码身份，不用短 `index`。原始帧只用于受控诊断 |
| `StrokeBatch` | 来源、连接代次、笔画 ID、序列、`down/move/up/cancel`，以及纸页、坐标、单位、可选压力与时间。无可靠页号时标为未知，不猜另一页；缺压力使用宿主样式，不伪造采样。对非法数值、未知坐标单位、超限或跨页未封笔画拒绝或标记中断 |
| `startInk(target)` / `accept(batch)` / `finish` / `cancel` | 宿主捕获已解锁且可编辑的目标窗口、笔记、编辑器实例、文档/选区书签及权限代次，返回仅供内部路由的输入会话。写入仍由用户在速绘中点「完成」提交；按原有 `drawing` 节点和保存队列持久化，普通 Undo/同步/备份不依赖智能笔插件 |

### 点读触发

1. 用户连接并授权指定笔，在设备设置主动进入「学习点读码」，实点后查看所识别的码及拟绑定动作。学习态不执行动作。确认后按「适配器/profile + 本机设备 + `codeNamespace`/`codeId`」保存唯一、默认可修改或关闭的绑定；重复键要求替换确认，不按注册顺序选胜者。
2. 用户在明确的笔记窗口开启「接收智能笔」，该窗口独占输入目标。只有当前连接且已授权的 `live` 点码命中本地绑定时才请求执行白名单命令；首个候选为「在本笔记打开速绘」，映射通过命令注册 ID，不执行设备给出的 URL、脚本、任意工具名、上传、解锁或删除，也不能解除权限或同步屏障。将来新增会写库或录音的快捷动作仍要宿主确认。
3. 同一次物理点按的重复通知经连接内去重和同码冷却合并；点码不能替代笔画边界。命令成功才反馈已激活，已打开同一目标的速绘时幂等，不重开或清空。未知/无效码仅在学习界面反馈；旧代次、离线回放、模拟源与失效目标均不执行。锁定、设置/模态占用、IME 正在组字、同步冻结和无可编辑目标时不抢焦点、不排队晚执行。

### 笔迹输入

用户可先手动打开速绘，也可在已布防窗口中由点码打开，或由首个有效在线 `penDown` 请求打开本笔记速绘。宿主持有同一绘图目标，并为打开到就绪期间的**首笔**保留小型、限时缓冲；仅在目标、连接和输入代次全部匹配后交付。打开失败或缓冲溢出丢弃整支未完成笔画并提示，不把首个 `move` 误当成另一笔开始。笔迹消费走批队列与画帧节奏，不逐点更新整棵 React 树；背压时可降采样 `move`，必须保留边界，无法保证序列时取消残笔，不跨丢包连线。

profile 将厂商坐标换算成纸张尺度；宿主按选定纸张和原绘图逻辑坐标做校验和映射，不使用原型的固定纸张比例或盲目裁剪越界点。缩放/旋转只改变视图投影；同一页内输入不会被手势挪位。笔迹流与本地触摸/触控笔共享速绘历史，不并发修改同一未结束笔画。断线、切笔记、锁定、授权失效或遇到同步/访问屏障时，废弃不可提交的目标与未完成笔画；若原目标仍有效，只允许用户手动完成已显示的完整笔画，不自动插到当前新笔记。`offline` 笔迹未来只能经独立导入预览/确认，按原设备文件/批次与内容去重，不能激活实时输入或命令。

## 4. 智能录音设备预留

录音设备走同一个设备注册与授权服务，但不假定音频一定通过 BLE。适配器要宣告并在连接后协商 `audio.import`（已有文件）、`audio.capture`（实时采集）及可选控制（开始、暂停、停止、设备状态）；BLE 控制、经批准的数据通道与系统音频输入分别验证。BLE 连通不能证明有音频传输，连接成功也不能自动切换本机麦克风或开始录音。优先验收「导入设备已有录音」，实时控制与流式采集需选定硬件后独立评审。

| 接口预留 | 归属和失败处理 |
| --- | --- |
| `listAudio(lease, cursor) → items`、`openAudio(lease, itemRef) → bounded stream` | 用户主动选文件和目标笔记。项目引用绑定设备/文件版本；可有大小、时长、格式和时间，不把文件名当身份或 MIME 依据。宿主流式暂存，检查字节数、容器、编码、时长及可用校验和；完整后预览并经既有附件提交与正文 ACK。取消、部分传输或断开不发布半成品，不删除设备源件；重复提交使用原操作回执 |
| `startCapture` / `pauseCapture` / `stopCapture`、`CaptureEvent` | 仅协商支持时提供。用户明确选择来源和目标，宿主创建唯一录音 owner；事件区分 `state`、有序音频 `chunk`、可选真实 `level`、`final` 与 `error`，绑定录音票据、设备租约与取消令牌。控制命令的发送成功不是录音已开始/暂停；以设备回执及本地可验证数据为准。流转入现有录音的宿主封存、重试、退出保护与附件链路，不开启第二个提交队列 |
| 媒体边界 | 实时断流、越序、写满或状态不明时显示中断，仅可显式保存经校验的完整分段；没有可用分段不创建卡片。切换到笔记 B 不能改变已建立在 A 的录音归属，A 权限失效不继续读入、不改投 B。已保存的是核心可读的音频附件，禁用设备插件仍可播放、导出和备份。无默认转写、上传或音频外发 |

## 5. 开发顺序与验收

先定接口与生命周期，用合成 profile 和事件验证契约；再实现编译期的原生蓝牙 broker、签发租约与平台权限；有实机证据后再引入 SmartPen 适配器。录音设备另行选定首个型号，先验证文件导入，再决定是否实现实时采集。不把此预留作为 M0/M1 的硬件实现门槛。

| 验收层 | 必测用例 |
| --- | --- |
| Profile / 授权 | 设备误匹配、系统拒绝、连接部分成功、越界读写、设备无响应时的扫描/连接超时、快重连后旧通知、同设备多窗抢占；停用和撤权后不再回调，未注册适配器及隔离页面无硬件入口 |
| 点读 | 支持的 `0xE1` 变体、短 `index` 碰撞、同码重复、非法帧、在线与离线混合、学习态不执行、跨锁定/切窗/IME 的竞态。唯一有效在线点按在原笔记打开速绘，不产生额外写入 |
| 笔迹 | `penDown` 到面板就绪的首笔、单位/页坐标、丢点与断线、同窗指针抢占、切笔记和同步竞态。真实提交后重开、Undo、禁用插件仍可读；以 macOS/Android 实包和实体纸笔分别验证，不用合成帧代替物理书写 |
| 音频 | 真机已录文件完整字节与可播放性、重复导入、断点能力、取消与失败不提交、跨笔记原 owner、停用不删除原文件。实时另验设备回执与音频完整性、前后台与退出保护，不将 BLE 配对当采集验收 |
