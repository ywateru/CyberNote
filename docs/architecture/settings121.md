## 云端同步

WebDAV（用户原文 webdev 按 WebDAV 实现）、S3兼容存储、GitHub私有仓库，以及 OneDrive／百度网盘，为用户自选云存储，与 CyberBus 的账号/设备认证分别呈现；不能要求用户登录 CyberNote 才配置自己的存储。CyberBus仍是应用账户和设备传输唯一所有者。各存储配置可分别保留，只有显式选中并启用的配置运行。

- WebDAV：HTTPS地址、目录、用户名、密码；GET/PUT以及有界目录创建；ETag条件写入。
- S3：endpoint、region、bucket、prefix、access key、secret、可选session token；AWS SigV4；ETag条件写入。支持用户配置的兼容服务。
- GitHub：owner/repo、branch、prefix、token；Contents API的blob SHA条件更新；遵循Contents API大小限制并给出明确错误，不静默截断。
- 远端是带版本的加密应用数据；密码通过Argon2派生密钥、随机盐和AES-GCM随机nonce，错误密码/篡改零导入；凭据、CyberBus grant、MCP授权和本机路径不进入备份或云端数据。状态DTO不回传密钥。保存凭据到本机私有状态文件，权限0600，写入原子化且损坏拒绝覆盖。
- 同步必须有有界超时、响应体/解密体/实体限制、单操作串行和条件写入冲突处理。不能把401/403、404、网络失败、解析失败视为远端空库。测试连接不得写入笔记。
- 同步笔记、附件及可移植设置时复用现有版本/冲突、Session保存屏障、Store事务、附件校验与事实事件；禁止让归档导入每轮重建ID造成无限重复。若使用归档快照传输，须实现稳定身份合并及冲突保留，不能用“上传/下载备份”冒充双向同步。
- 云端逻辑资料库身份与Store本机/账户同步身份分别固定。云端身份用于配置/密文/确认票据绑定；Store身份用于本机版本向量及当前库校验，两者不要求UUID相同。不得静默替换CyberBus已拥有的账户workspace、设备身份或grant，也不能仅因两端既有本机/P2P/账户workspace不同便拒绝用户明确确认的云端合并。复用底层同步版本时保留账户隔离；独立快照合并也须固定实体ID与并发版本，不能用导入复制规避冲突。测试覆盖两个既有不同同步身份的本机云端往返后，各自原Store身份不变。
- 首次拉取、恢复、覆盖远端均需明确确认与预览；当前本机内容先保留可恢复版本。远端冲突不丢弃本地分支。下载时不持Session锁，提交前重新核验Token/库身份和版本；窗口活动保存不被旧快照覆盖。
- 自动同步可选关闭/3/15/30/60分钟，只在应用运行、显式启用且权限有效时执行；默认关闭。不因仅打开设置、发现设备或读取状态开始内容传输。

### 首批网盘 OAuth（已实现，待真实账号验收）

OneDrive 和百度网盘通过 OpenList 兼容授权取得 refresh token，不使用 CyberNote 自有厂商开放平台应用。该兼容桥的端点、令牌捕获、风险披露和验收见[多网盘登录与同步调研](../research/cloud-drive-sync-20261121.md)。

- 授权：用户在应用内受控 WebView 登录，原生拦截 OpenList 固定回调的 URL fragment，校验 `driver_txt` 后保存 refresh token。授权对象是 OpenList 应用，不是 CyberNote；OneDrive 权限为 `Files.ReadWrite.All`，百度为 `basic,netdisk`，设置页必须在打开登录前明确披露。
- 授权窗口：`/requests` 会设置 `driver_txt`／`server_use` Cookie；原生必须把它们注入专用 WebView 数据存储后再打开厂商页。OneDrive 回调还要求 `server_use=true`；百度 OAuth 回调不返回该字段，只校验 `driver_txt=baiduyun_go`。Cookie 缺失、值不匹配或 issuer 不一致时失败，不打开登录页。
- 凭据：新 OAuth 凭据使用云同步专属加密记录，与 CyberBus grant、账户库、Store 身份和保存队列分离。配置只引用 `credential_id`，令牌不进入日志、备份、云快照或 renderer。
- OneDrive：个人版使用 Graph 显式提交上传会话，最终 `PUT` 以 `If-Match`（更新）和 `If-None-Match: *`（创建候选）裁决并发；工作／学校版文档化完成方式是零长度 `POST`，最终条件实测通过前只读。个人版代码按双向能力发布，真实账号并发实测仍是验收门槛。
- 百度：没有可用的内容条件提交，默认使用不可变 heads 提供多设备读写；读取每个 writer 的最新 head（下载、大小校验或解密失败时回退上一份），解密后合并，再写新的 head，不覆盖旧对象。`ReadOnly`／`SingleWriter` 仍可选；并发编辑保留为冲突，真实多设备并发待验收。heads 使用 `writer_id`／`seq` 可信排序；`create`／`precreate` 使用 `rtype=3` 与 MD5 元数据。当前固定 `/CyberNote`，但开放平台文档的 `/apps/{appname}` 限制和 OpenList 应用名尚未经真实账号确认；若被拒绝，必须改为可配置根目录或暂停百度写入。
- 失败：授权过期进入重新连接；网络失败保留连接；原生登录窗口失败或关闭时移除 handler，失败状态可重试；断开只清本机凭据，保留本机笔记和远端密文。OpenList 服务不可用时暂停受影响网盘，不静默切换 issuer 或删除数据。

实现位置：OpenList 契约与回调解析在 `src-tauri/src/cloud_sync/auth/openlist.rs`，凭据加密在 `auth/vault.rs`，连接状态机和命令在 `runtime.rs`／`commands.rs`，OneDrive／百度读写分别在 `remote/onedrive.rs`／`remote/baidu.rs`。`connectionInfo` 可指定 provider，设置页刷新当前展示的连接。macOS 与 Android 的原生窗口在 `plugins/tauri-plugin-notes-auth` 的 `openCloud`／`closeCloud`，不新增 renderer 可调用的原生接口。当前 OneDrive 个人版按双向能力发布，工作／学校版固定只读；百度默认多设备读写，只读／单写者可选。真实账号并发、百度真实写入路径和真机行为仍待验收，不能把自动化 fixture 当作完成证据。

跨命名空间桥接先验证原始WireVersion及digest，再保持实体ID、vector、payload，转换传输副本到云规范UUID并重新seal；入本地Store时同样验证后转换回当前Store workspace，不调用adoption。相同逻辑版本往返必须相等。跨workspace的digest排序可能导致并发冲突在各端投影不同正文，双方完整保留heads并显示冲突；用户显式解决后传播收敛，不以自动选中某分支宣称无冲突。收件的持久接受点在有效确认及fence复验之后；关闭云停止新接收/发送，已提交共享inbox的版本按既有安全屏障继续恢复，不能承诺撤回已接受内容。

云端可移植设置采用版本化显式白名单（由模块契约列出并测试），缺失键保留当前值，显式false/空值按字段语义应用，未知/本机字段不发送。各设置头有因果版本与CAS，不把整行settings塞入wire。账号授权、选中项、窗口、设备呈现、目录和云/备份/更新调度开关为本机状态，不因远端内容而启用。

原生模块 `cloud_sync` 提供独立DTO及命令，前端 `cloud-sync` 仅调用这些命令，测试不依赖真实服务或用户配置。实现者先固定并反馈确切命令注册及初始化需求，由整合任务接入两套invoke handler。可使用既有应用宿主注入的受检归档/同步端口；不能新增第二个Store。

## 导入、导出与备份

继续使用原生文件选择器、现有 `export_archive`/`import_archive` 与保存屏障；增加加密导出/导入的选择时沿相同验证路径。导入显示预览和确认，错误密码或损坏文件不写入。保留Apple备忘录导入。设置、完整笔记正文和附件原字节的往返由真实Store测试证明；授权和凭据不导出。

参考截图的导入/导出、自动备份（关闭/1小时/6小时/1天/1周）、保留份数（3/7/14/30）、备份文件夹、版本列表/立即备份、数据文件夹显示应有真实能力。账户授权不提供“备份登录信息”选项，因为本项目本机授权不可移植。默认自动备份关闭，已存在备份不因开关关闭而删除；保留清理只处理自身已验证版本，恢复前确认并保护本机数据。数据文件夹移动涉及lease和重启，未实现安全搬迁前不提供可点击假入口。

本地版本恢复沿既有归档的“合并为副本并应用归档设置”语义：预览明确新增内容/保留当前内容和设置影响，不称原位时点回退。恢复前保护副本必须在同一全窗口保存屏障后、实际导入前完成并验证；它保护当前业务投影，不声称包含全部同步历史/inbox。现存heads/墓碑不通过删除同步表来回退。预览绑定不可变bytes/hash、版本ID、目标Store instance/generation及限时一次性确认；已提交后刷新失败保留提交事实，不自动再导入。普通归档settings沿原验证行为，私有模块配置不放入归档，恢复不启用云/备份/更新任务。

本地备份默认在应用私有目录的专属受管子目录，先经Session受检stage_archive捕获，再由备份owner发布，普通用户export_archive仍禁止覆盖活库。桌面提供真实外部目录更改/显示；Android本轮使用应用私有备份目录并明确注明，不显示尚无SAF tree适配的“更改外部文件夹”动作，单文件导入导出继续现有系统选择器。卸载会删除Android私有备份，界面须说明。

快照捕获与apply分开协调：后台任务先probe所有有效窗口，活动录音/IME/附件时推迟；排空正文及偏好保存后短暂prepare冻结，受检stage捕获完即release。不能在Session锁内等待ACK或网络。云apply另走共享quiet计划并复验完整sync/media generation、Store instance、Token、云配置代次和participants；`application_generation`不能替代收件generation。不得将App.archiveRunning与拒绝该标记的quietHost机械嵌套造成自阻塞。

## 更新

「关于」提供版本、版本说明、检查状态、下载进度和重试。发现较新版本才显示徽标。检查只读发布元数据，点击徽标或下载动作才请求安装包。更新源固定本项目 GitHub Releases（ywateru/CyberNote），版本源为发行标识或 `package.json` / Rust 包版本。支持手动检查、启动时或定时检查、稳定版、尝鲜版和每日版。稳定版接收正式发布，尝鲜版也接收预发布，每日版接收含 `daily` 标识的预发布。只提供比当前版本新的匹配平台和架构产物。

每日版标签采用 `v<core>-preview.<N>.daily.<YYYYMMDD>`，既保留可排序的预发布序号，也明确其每日版身份。尝鲜版仍可看到普通 `preview.<N>` 和每日版；稳定版只看到无预发布后缀的标签。没有对应通道发布与网络失败必须区分。

下载前确认发布信息，下载有界并校验发布 SHA-256 及包身份。新版本不可用、无网络、缺少当前平台产物、校验失败须明确区分。macOS 应用内更新使用 ad-hoc 签名的 ZIP，DMG 用于手动安装。Android 优先选择签名 APK，旧 Release 的未签名 APK 保留下载兼容。Android 自动更新止于校验及下载，由用户在系统安装器中打开 APK，覆盖安装须满足系统签名检查。

macOS 安装 lease 需先原生确认、完成全窗口正文/偏好保存与录音封存并阻止新编辑，再经既有 orderly quit。helper 等待原 PID 真正退出后替换，启动 ack 仅在新宿主的存储、窗口和退出协调均就绪后发送，失败或超时保留恢复事务。

检查和下载不发布新版本、不推送Git、不触动现有用户库。离线fixture覆盖feed、semver、平台选择、校验和下载失败。原生模块 `software_update`、前端 `software-update` 的创建、命令注册、轮询/计时器清理和生产UI入口由整合任务核验。

## 验证

先做模块针对性检查及独立审查，再做组合 typecheck/build、版本一致性、账户边界与导入/备份回归。UI需真实React浏览器截图（桌面浅暗/窄屏/移动），并与截图1/参考源码对照。云端用本地HTTP fixture验证真实请求、ETag/SHA并发拒绝、S3签名、密文和内容合并；不使用用户服务凭据。检查更新用本地feed和损坏包fixture。不能把fixture或编译通过称为真实WebDAV/S3/GitHub账户、原生安装或手机验收。
