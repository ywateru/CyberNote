# 从系统 Apple 备忘录导入（Mac）

用户目标：在Mac客户端直接把系统自带“备忘录”的数据复制进本应用；源笔记、文件夹和附件不得被修改、移动或删除。研究依据以本机 Notes.sdef、CocoaStandard.sdef、实际只读读取和一手项目源码为准，结果归档于research/apple-notes-import92。

固定JXA与Rust host的字段、调用允许集合及错误分类以[来源协议v1](apple-notes-source-protocol.md)为准。

## 数据与只读边界

仅Mac显示入口。使用固定的原生只读Apple Events/JXA适配器读取账户/文件夹层次、稳定ID、标题、HTML正文、纯文本、创建/修改时间及附件。附件的save只允许写入本应用新建且拥有的暂存目录，含义是导出副本，不保存note本体；禁止source make/set/delete/move/import、源数据库写入或checkpoint、改变源文件权限、终止Notes。正常读取无需先导出系统Notes备份，也不要求用户手工逐条复制。

账户和文件夹成为目标中的普通文件夹，置于独立“来自 Apple 备忘录”根下，不覆盖现有文件夹或笔记。正文转为现有受校验编辑器schema，尽量保留标题/段落/换行、粗斜体/删除线/链接、列表/清单、表格及附件顺序；安全转换禁止执行源HTML、事件处理器或自动下载远程资源。原始HTML和必要的源元数据保留为本地导入原始记录（独立文件，不在界面执行），不能通过无提示纯文本降级丢失源信息。不能完整转换的样式/对象须在结果明确报告，仍保留原始记录。图片、音频、PDF及其他文件导出为目标独立受管文件，重写附件ID与正文引用；不在SQLite存放原文件字节，不引用源附件路径。清单/表格或特殊对象能力不足时须依据研究补充真实映射或明确保留，不假装支持。

锁定、不可访问、云端未下载或导出失败项目逐条列出原因；不解锁、不改源密码、不将未读取内容伪造成空笔记。单条缺失附件不得悄悄以“完整成功”提交。不可读取项可跳过，但结果必须显示准确成功/跳过/失败数量及详情，并允许后续重试。

## 导入过程与目标持久化

扫描/源附件导出在Session锁外运行；取消只结束本轮拥有的工作/脚本，不杀Notes。原始读取结果留本机，不写用户正文、标题或源ID到控制台、仓库、测试日志。正常应用界面可展示源标题与文件夹以便选择。

受管附件读入前先按文件元数据累计单项与批次预算，不先把整条所有文件加载后才判断合计。等待系统导出时检查自有暂存文件增长与磁盘余量，越限停止本轮自有脚本并报告，不能仅靠脚本超时。Apple Events save由Notes进程执行，停止调用方不等于能强制中止Notes内部写入；此监测是及时检测/取消与安全清理，不宣称文件系统硬配额或终止源App的能力。

用户预览来源/数量并开始复制；导入保留源创建/修改日期。目标写入遵守现有Session授权、元数据、附件校验和崩溃恢复约束，不能替换目标数据库或设置、丢失当前编辑草稿/录音。复用已有存储/导入设施时必须验证其设置合并和冲突语义是否满足此处，不可直接套用会覆盖本地设置的备份恢复流程。

每条目标保存来源ID和内容指纹的本地导入记录，用于重试：相同来源/相同内容不重复创建；源有改动时创建更新副本，保留用户已编辑的旧导入笔记，不静默覆盖。稳定来源标识不依赖可变文件夹名或数组序号。成功记录与对应目标数据一起持久化，失败不记成功；来源信息不授予对Apple Notes的写能力。所有外部路径/名字是不可信数据，不作shell代码或目标路径拼接；附件按随机受管名保存，拒绝路径穿越、符号链接替换和未知token。

只有存在新内容的导入批次才创建本批专属的“来自 Apple 备忘录”目录及源账户/文件夹层次；全部已存在时不新增空目录。新批次不复用用户可能已移动或改名的旧导入层次，避免把新源内容写入用户自行组织的目录。来源/指纹记录可保存为与真实目标绑定的受管原始记录文件；以真实笔记/附件拥有关系重建去重信息，不能仅相信已失去目标的独立成功标记。

新增独立原始记录纳入现有数据管理的总占用/文件明细和完整备份。导出再恢复时原始记录及目标引用仍可核对；成功来源账本不得指向不存在的目标或原始记录。复用现有受管文件/归档机制满足一致性，不另造脱离管理的文件目录。

## 界面与交互

入口在现有设置→数据，备份区旁增加“从 Apple 备忘录导入…”，不把它与本应用备份导入混用。

```
设置    数据
  本地空间总览 / 分类明细
  数据导入
    从 Apple 备忘录导入…   （仅 Mac）
  本地备份：导入备份 / 导出完整备份
```

```
从 Apple 备忘录导入                         关闭
将笔记复制到本应用，系统备忘录中的内容保持不变。
[读取系统备忘录] → 来源账户/文件夹与笔记数量预览
  可读取 N 条，锁定/不可读 M 条（可查看原因）
[开始导入] / [取消]
  正在读取/复制/保存… n / total
  完成：导入 X，已存在 Y，跳过/失败 Z [查看详情] [完成]
```

使用现有设置视觉与焦点/滚动规范；忙碌时防重复请求，关闭/取消不再让迟到响应覆盖新页面。录音或未提交草稿冲突时沿用已有明确阻止/安全提交机制，不用全屏闪烁遮罩。首次系统自动化授权缺失时显示具体原因和系统设置入口说明；权限拒绝、源App无数据、超时与部分结果有可区分状态，不反复弹系统权限。

## 必须验收

1. 固定脚本/原生适配器无源写入命令，实际读取前后源ID/数量/正文与附件摘要（私有临时证据）保持；不能以整个源SQLite文件时间不变替代数据保持，因为源App可能正常后台维护。
2. 真实目标Store中新建独立文件夹、正文、日期和附件；重开后仍在，原目标笔记/设置保持，重复导入不重复，相同ID内容变更保留旧副本。
3. 富文本/清单/表格/图片/音频/普通文件、安全HTML、锁定项、导出失败、取消、权限拒绝、路径攻击与崩溃/事务失败边界有针对性检查。
4. 实际App DOM完整入口→预览→开始→结果；命令调用/HTML检查可自动化，OS边界用固定合成源测试，但至少一次实际只读Apple Notes来源→隔离目标Store的集成证据。私有源内容不进入仓库；不为验收删除/修改源数据。
5. Mac准确构建并独立核包、实际新功能可运行；Android保持现有包和原现场，跨平台编译不能引入Mac专有错误。完整未验证范围必须说明。
