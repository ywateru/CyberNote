# 从 Apple 备忘录导入（Mac）

在 Mac 客户端打开 **设置 → 数据 → 从 Apple 备忘录导入**。本功能把所选内容复制到本应用；不会移动、修改或删除系统备忘录中的原件。

## 操作

1. 点击 **读取系统备忘录**。若 macOS 询问是否允许控制“备忘录”，允许后才能通过系统接口读取。拒绝授权会在应用中报告，可稍后授权再重试。
2. 在预览列表中按账户/文件夹路径核对来源，勾选笔记，或点击全选。锁定或不可读项目不能勾选。
3. 点击 **复制所选 X 条**，等待结果。进行中可以取消；已完成的目标提交会按实际结果保留，取消不会回滚源数据。
4. 查看 **结果详情**，确认已复制、已存在、跳过以及部分格式保留的数量与原因。

新增内容放在本批次独立的 **来自 Apple 备忘录** 根文件夹下，保留来源账户/文件夹层次及创建、修改时间。全部内容已存在时不会创建空目录。读取和复制期间若有编辑草稿、录音或目标存储忙碌，应用先处理相应的保存/互斥边界。

## 重复导入和原始记录

相同来源且内容相同的笔记自动跳过。源内容变化后重新导入会创建新副本，保留之前导入和本地编辑的内容。

从 APP93 / Mac31 起，原始 HTML 和必要来源信息作为内部受管记录保留，**不会添加到笔记正文或普通附件列表**。此前已导入的记录也使用相同显示规则；用户自行添加的同名 JSON 仍正常显示。部分无法映射的样式会在结果中说明，内部原始记录随数据管理、完整备份与同步保存，不在界面执行源 HTML，也不提供普通“保存附件”入口。图片、音频及其他用户文件仍按本应用的受管附件方式显示和保存。

## 已验证与限制

实际系统来源到独立目标库的读取、导入、重开、重复跳过以及源采样字段前后保持已有验证。富文本、清单、表格、图片/音频/普通文件、取消和故障边界同时有合成来源测试；它们不等于每种真实 Notes 原生对象均已成功导出。

本机实测的三个来源附件导出失败，系统返回 -10000 且未产生文件。无法据此判断对象类型、云端状态或权限原因。附件缺失或导出失败的笔记会明确跳过，不作为完整成功；锁定笔记需要用户先在系统备忘录中正常解锁后另行重试。真实图片/音频/PDF/特殊对象的系统导出保真范围仍需根据后续使用补充。

macOS 自动化用途文字和签名 entitlement 由打包流程检查；这不替代每台 Mac 自身的系统授权。产品只读取本机系统接口，没有 iCloud 登录或远程读取功能。

导入基础能力与真实来源限制见[APP92 交付记录](verification/apple-notes-import92/DELIVERY.md)；内部记录显示调整与附件菜单的当前进度见[APP93 恢复状态](plan/attachment-context93-state.md)。

## 附件菜单（Mac31）

在笔记中的图片、已保存音频、视频或文件卡上点击右键，或聚焦附件后按 Shift+F10。普通附件可保存原文件、显示信息、从备忘录中移除；图片还可预览，音视频可播放或暂停。移除支持撤销和重做，不会直接删除底层文件而破坏撤销。

正在录制的临时卡需要先完成保存，才能使用保存文件或移除操作；录音期间其他已保存附件仍可使用。切换笔记会关闭菜单和信息面板，保存对话框期间切换笔记也不会把旧附件操作应用到新笔记。
